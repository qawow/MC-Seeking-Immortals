## 🔴 关键阻断问题（P0）

### 1. 术法系统几乎不可用（2.7% 接线率）

**问题严重性**: 🔴 **游戏核心玩法缺失**

**发现**:
- JSON 术法总数: **747 条**
- SkillType 枚举: 388 个
- 已通过 `registerTechniqueAlias()` 接线: **仅 20 条 (2.7%)**
- 未接线术法: **727 条 (97.3%)**

**已接线的 20 条术法**:
```
fireball, earth_spike, five_elements_escape, ice_cone, thunder_strike,
earth_escape, aura_detection, entangling, voice_transmission, object_control,
quicksand, water_shield, earth_prison, wind_binding, wind_wall,
big_dipper_sword_array, light_body, soul_search, demon_subdue
```

**影响**:
- 玩家学习功法后无法释放绝大多数术法
- 110 条 buff_self、110 条 projectile、95 条 aoe 术法完全不可用
- 47 条终极技、21 条秘术无法释放
- 门派核心术法（道家清虚系、佛门天澜系、魔道天魔系）无法使用

**根本原因**:
```java
// TechniqueDataManager.java - JSON 加载后未建立 ID 映射
private void loadFromJson(JsonObject json) {
    String id = json.get("id").getAsString();
    techniqueMap.put(id, technique);  // ← 仅存储到 map
    // ❌ 缺失: SkillEffectRegistry.registerTechniqueAlias(id, skillType);
}
```

**创建任务**: #1 修复 97.3% 术法未接线问题

## ⚠️ 高危安全漏洞（需立即修复）

### H1. 储物菜单 TOCTOU 竞态条件

**位置**: `StorageBraceletMenu.clicked()` L80, `removed()` L97

**漏洞**: 玩家可在菜单打开期间扔出/交易储物镯，服务端仍持有陈旧引用写入

**攻击场景**:
1. 玩家 A 打开储物镯菜单（镯子在主手）
2. 玩家 A 按 Q 键扔出镯子
3. 玩家 B 捡起镯子
4. 玩家 A 在菜单中放入钻石
5. **钻石写入到玩家 B 的镯子**

**创建任务**: #4 修复储物菜单 TOCTOU 漏洞

---

### H2. 拍卖 settle 幂等性不完整

**位置**: `AuctionSoftService.settle()` L314-375

**漏洞**: Crash 在 `markSettled()` 和 `won` NBT 之间，重启后可重复领取奖励

**攻击场景**:
1. 玩家出价 1000 灵石拍下极品法宝
2. 服务端调用 `settle()` 开始交付
3. 在 `markSettled()` (L346) 后 Crash
4. 重启后 `won` 标记缺失，玩家再次 settle
5. **法宝重复交付**

**创建任务**: #5 修复拍卖 settle 幂等性

---

### H3. 秘境 owner-session 绑定可绕过

**位置**: `SecretRealmRewardService` 奖励交付路径

**漏洞**: 部分奖励路径未检查 `activeSession()` 的 owner UUID

**攻击场景**:
1. 玩家 A 开启秘境"古修士洞府"
2. 玩家 B 用 `/tp` 传送进入同一维度
3. 玩家 B 击杀 Boss，触发奖励箱
4. **玩家 B 可领取玩家 A 的首通奖励**

**创建任务**: #6 完善秘境 owner-session 强校验

---

### H4. 任务 hook 当前步骤可跳过

**位置**: `QuestHookRuntime.tryAdvanceByHook()`

**漏洞**: 无 authored hook 的阶段允许重复推进

**攻击场景**:
1. 玩家接受任务"寻找失踪的师兄"
2. 任务有 5 个步骤，步骤 2-4 无 authored hook
3. 玩家通过客户端 mod 重复发送 `QuestTrackerActionPacket("advance:chainId")`
4. **直接跳到步骤 5，领取最终奖励**

**建议修复**: 为每个 stage 添加"已完成"标志，advance 前检查幂等性

## 📝 技术债务清单

### 代码层面
1. **术法 ID 别名注册机制缺失** - 需要在 TechniqueDataManager 加载后调用 SkillEffectRegistry
2. **功法配置数据不完整** - cultivation_methods JSON 缺少 layers_max/cultivation_costs
3. **网络包校验不统一** - 部分 C2S 包缺少权限等级检查
4. **事务原子性保护不完整** - 商店/拍卖/宗门需要先写账本再交付

### 数据层面
1. **功法矩阵空白** - 14 个功法的 matrices 字段为空数组
2. **术法元素枚举不足** - 缺少 EARTH/YIN/YANG/SOUL/BLOOD 等常见元素
3. **材料 ID 映射不完整** - 部分多方块结构材料无法解析为物品
4. **MP 序列数据缺失** - 9/92 结构无建造指引

### 美术层面
1. **功法手册占位贴图** - 60 个手册全部使用 *_placeholder.png
2. **法宝占位模型** - 大量法宝使用 vanilla 剑/锭/宝石模型
3. **阵核复用贴图** - 15 个阵核复用 spirit_gathering_array 贴图
4. **结构占位方块** - 部分结构使用通用方块占位
