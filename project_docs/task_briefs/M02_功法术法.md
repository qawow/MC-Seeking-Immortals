# M02 功法与术法

- 分支：`task/m02-techniques` ｜ worktree：`D:/codex/mc-mod-worktrees/m02-techniques`
- 前置模块：M00（346/747 基线裁决）、M01（境界门槛 API）、M14（状态注册表，可先桩）
- 优先级：P0（EXPANSION_ROADMAP：术法 effect 实装）

## 目标

把 747 部功法 / 136 部功法体系（cultivation_methods）语料接进 `TechniqueDataManager` 加载管线，补齐语料引用但尚未实装的术法 effect，落地技能树与功法冲突矩阵。

## 功能点清单（可勾选）

- [ ] 按 M00 裁决的基线，扩量加载 `文本材料/data/techniques/`（19 个分类文件，747 条）：`TechniqueDataManager` 服务端加载 + `ClientTechniqueData` 内建摘要镜像同步扩量。
- [ ] 术法 effect 实装：盘点 747 条 technique JSON 引用的 effect id，与 `skill/effect/spell/`（现约 44 个硬编码类）求差集，为缺失 effect 新建 Java 类并注册进 `SkillEffectRegistry`。
- [ ] 功法体系落地：`cultivation_methods.json`（136 部）→ 现有 method 学习/布局管线（`MethodAction`/`SyncMethodLayout`/`MethodLayoutAction` 包已存在，验证容量与字段够用）。
- [ ] 技能树落地：`skill_trees.json` + `skill_tree_layer_schema.json` → `SkillTreeAction`/`SyncSkillData` 管线与 `LifeSkillService`/`SpecialSkillService` 对齐。
- [ ] 功法冲突/兼容矩阵：`manual_catalog` 冲突矩阵 → `TechniqueGateService`（现 classpath 直读，409/436 行）学习校验。
- [ ] 小说系功法：`novel_cultivation_*` 系列入加载范围并通过校验。
- [ ] 服务端校验完整性：`ReleaseTechniquePacket` 路径上槽位/已学/冷却/灵力校验对新增功法全部生效（客户端不可信原则）。

**语料侧（本模块拥有）**
- `文本材料/data/techniques/`（19 分类文件 + index.json 内容层面；index 拼接逻辑归 M00）

- `文本材料/data/skill_trees.json`、`skill_tree_layer_schema.json`
- `文本材料/data/manual_catalog*`（含冲突矩阵）
- `文本材料/data/novel_cultivation_*`、`techniques_sample.json`

**模组侧（本模块拥有）**
- `TechniqueDataManager`、`ClientTechniqueData`、`TechniqueManualItem`
- `skill/` 包：`SkillType`、`CultivationSkill`、`SkillCategory`、`LifeSkillService`、`SpecialSkillService`、`TechniqueGateService`
- `skill/effect/`：`SkillEffect`、`SkillContext`、`SkillEffectRegistry`、`spell/` 全部术法类
- `data/seeking_immortals/cultivation/`（随 jar 的功法 JSON）
- 相关屏幕归属：`TechniqueEditScreen`、方法树屏幕的**数据容量适配**（UI 风格归 M16 之前已统一，勿重构）

## 依赖前置库

- Forge 资源管理器（`server.getResourceManager().listResources("cultivation", *.json)`——数据包可扩展；客户端镜像是 classpath-only，扩量时注意两侧一致）。
- Forge 网络：`ReleaseTechniquePacket`、`SetTechniqueSlotPacket`、`SyncLearnedTechniquesPacket`、`SyncLearnedMethodsPacket`。

## 接口交叉（谁提供 → 谁消费）

- **M02 → M15**：`SkillEffectRegistry` 效果 id（法宝主动技引用）。
- **M02 → M10**：效果 id（妖兽/灵宠技能引用）。
- **M02 ← M01**：学习门槛（境界/灵根/路线）查询。
- **M02 ← M14**：统一状态 id 注册表（burn、frozen、soul_shock、illusion 等 —— 术法施加状态时引用，M14 未合并前用字符串常量桩）。
- **M02 ← M00**：功法数量基线与索引再生成流程。

## 验收与红线

- 每条已加载 technique 的 effect id 都能在 `SkillEffectRegistry` 解析（新增校验测试）。
- 槽位数保持 `TECHNIQUE_SLOT_COUNT == 7` 不变。
- 神通/禁术类高阶术法的境界门槛必须服务端强制（红线：越境界施放）。
