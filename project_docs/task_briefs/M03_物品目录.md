# M03 物品目录与批量注册

- 分支：`task/m03-item-catalog` ｜ worktree：`/root/mc-mod-worktrees/m03-item-catalog`
- 前置模块：M00
- 优先级：P0（物品 id 权威是半数模块的前置）

## 目标

把语料侧上万条物品描述（丹药 114、灵草 79、材料 461、符箓、货币、功法书、傀儡部件等）统一收敛到 `ModBulkItems` 批量注册管线与 `catalog_bulk_items.json`，成为全模组唯一的"物品 id 权威 + 别名解析"提供方。

## 功能点清单（可勾选）

- [ ] 目录对账：`item_id_index` + `item_id_aliases` ↔ `assets/seeking_immortals/catalog_bulk_items.json`（现约 559 个目录载体物品）逐条对账，列出缺失/多余清单。
- [ ] 批量注册扩容：把对账缺口按类别（pills/herbs/materials/consumables/currency/manuals/talisman/puppet_parts/block_items）补进 `ModBulkItems` 管线，含创造标签、双语言 lang、模型占位。
- [ ] 符箓目录：`talisman_catalog` + 品阶 schema → 符箓物品注册与品阶属性（消耗策略归 M14 的 `TalismanConsumePolicy` 接口，本模块只注册物品）。
- [ ] 傀儡部件目录：`puppet_parts_catalog` → 部件物品注册（组装配方归 M04，傀儡实体归 M10）。
- [ ] 描述文本落地：`item_descriptions_v95–v118`、`novel_items_*` → tooltip/lang 生成流程（走 M00 索引再生成）。
- [ ] 别名解析 API：提供 `resolveCatalogItem(String idOrAlias)` 供下游模块查物品，禁止下游硬编码注册名。
- [ ] 方块物品：`block_items_catalog` 中纯展示型方块物品的注册补齐（功能性方块归各玩法模块）。

## 涉及文件

**语料侧（本模块拥有）**
- `文本材料/data/` 下：pills/herbs/materials/consumables/currency/manuals 各目录文件、`talisman_catalog*` 及品阶 schema、`puppet_parts_catalog*`、`item_id_index*`、`item_id_aliases*`、`item_descriptions_v95`–`v118`、`novel_items_*`、`block_items_catalog.json`

**模组侧（本模块拥有）**
- `registry/ModBulkItems`、`assets/seeking_immortals/catalog_bulk_items.json`
- `registry/ModItems`（779 行，仅"新增物品注册"段落；他人类目物品行为类不动）
- `item/pill/`（`CatalogPillItem`+Type、`PillCategory/Quality/Type` 的**目录映射**部分；consumePill 效果归 M04）
- `item/material/`（`MaterialType/Category/Rarity`、`BaseMaterialItem`）
- `assets/seeking_immortals/lang/zh_cn.json`、`en_us.json`（物品条目段）
- `assets/seeking_immortals/models/item/`（占位模型）

## 依赖前置库

- Forge `DeferredRegister`/`RegistryObject`（注册在类初始化期读 classpath JSON —— 注意 `ModBulkItems` 在 mod 构造早期执行，JSON 结构变更要保守）。
- `CreativeModeTab`（3 个现有标签页）。

## 接口交叉（谁提供 → 谁消费）

- **M03 → M04/M05/M08/M09/M10/M11/M15/M16**：物品 id 权威与别名解析（配方原料/产物、商店货架、贡献兑换、副本掉落、妖兽材料、任务奖励、法宝物品、图鉴条目全部经此查询）。
- **M03 ← M00**：id_map（`reference/text_material_id_map.json`）再生成流程。
- **M03 ← M01**：无运行时依赖（物品使用门槛由各玩法模块判定，注册本身不依赖境界）。

## 验收与红线

- 每个新注册物品必备：创造标签 + zh_cn + en_us + 模型 JSON（占位纹理允许，禁止删既有占位资源）。
- 红线（DESIGNER_HANDBOOK §5）：掌天瓶/绿液等唯一物品**不得**进入批量注册的可堆叠/可交易通道；唯一物品永不复制。
- `./gradlew build` 绿 + 游戏内创造标签页抽查无红字（missing texture 允许、missing model/lang 不允许）。

## 工作流提醒

按 README 通用工作流。物品注册属代码+资源改动 → 升 mod_version；不改包 → 协议保持。
