# M13 维度与飞升

- 分支：`task/m13-dimensions-ascension` ｜ worktree：`/root/mc-mod-worktrees/m13-dimensions-ascension`
- 前置模块：M00、M01（飞升境界门槛）、M07（传送阵判定）、M11（任务 flag，可先桩）
- 优先级：P2

## 目标

落地五界宇宙观的维度层：维度注册表、灵界接口、飞升流程、空间节点与飞行载具，向区域（M06）和秘境（M09）提供维度 id 权威。

## 功能点清单（可勾选）

- [x] 维度目录：`dimensions_catalog.json`（schema 10，cosmology_five_realms）+ `dimension_registry` ↔ 现有 11 个 dimension + 10 个 dimension_type JSON 对账，补缺失维度的数据包 JSON。
- [x] 维度 id 注册表：对外提供 `DimensionRegistryService`（id、所属界、境界带、进入条件），`SpiritualAuraManager` 已知的 tianyuan/spirit_fengyuan/yin_ming_pocket/nether_river_pocket/demon_rift 全部纳入。
- [x] 灵界接口：`spirit_realm_interface` + `mortal_to_spirit_bridge` → 凡界↔灵界通道规则（开启窗口、单向性、损耗）。
- [x] 飞升流程：`ascension_flow` + `ascension_loadout_v95` → 飞升条件（境界=M01、任务 flag=M11、渡劫=M01 TribulationService）→ 跨界传送 → 装备/物品重置（loadout 白名单）。
- [x] 空间节点：`spatial_nodes_catalog` → 传送阵网络节点（结构判定消费 M07 的 immortal_teleport_grand_array 等）。
- [x] 阴曹地府集群：`yin_underworld_cluster` → 阴界维度组与鬼修路线（M01）联动的通行规则。
- [x] 飞行载具：`flight_vehicles` → `SpiritBoat` 扩展 + `FlyingAuthority`（境界/维度别飞行许可）+ flying_boat_dock（M07 判定）。
- [x] 跨维度传送的服务端校验与冷却（禁止客户端指定目标维度直传）。

- Forge/vanilla 数据包维度体系（dimension/dimension_type JSON）、`Entity#changeDimension` 传送 API；`SavedData`（传送网络节点）。

## 接口交叉（谁提供 → 谁消费）

- **M13 → M06/M09/M10**：维度 id 注册表（区域绑定、秘境口袋维度、刷怪维度键）。
- **M13 ← M01**：飞升境界/渡劫门槛。
- **M13 ← M07**：传送阵/船坞结构 formed 判定。
- **M13 ← M11**：飞升前置任务 flag。

## 验收与红线

- dimensions_catalog 与数据包 JSON 一一对账（校验测试）；缺失维度有明确"暂缓"标记而非静默跳过。
- 飞升 loadout 重置必须有确认流程与备份箱机制，禁止直接销毁玩家物品。
- 红线：唯一物品在飞升重置中保留（白名单强制包含）。
