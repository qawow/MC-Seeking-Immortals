# M06 区域与世界事件

- 分支：`task/m06-regions-events` ｜ worktree：`D:/codex/mc-mod-worktrees/m06-regions-events`
- 前置模块：M00、M13（维度 id，可先桩）
- 优先级：P0-C（EXPANSION_ROADMAP 方向 C：region cards 是 P0 且当前**零 Java 消费者**）

## 目标

给已随 jar 发布但无人消费的 23 张 region cards 建立首个运行时消费者：region_id 注册表、区域→物品/刷怪/事件的查询入口，以及每日随机事件调度，成为所有"按地区差异化"玩法的空间底座。

## 功能点清单（可勾选）

- [ ] Region 注册表：读入 `data/seeking_immortals/text_material/region_cards/`（23 文件）建立 `RegionRegistry`（id、名称、境界带、所属维度、风土参数），并接入 `WorldpackDataService`（现读 worldpack/{regions,...}，BASE_PATH 第 19 行）或新建服务二选一——**禁止**两套 region 定义并存，需给出归一方案。
- [ ] 区域→物品映射：`items_by_region` → 查询接口 `itemsForRegion(regionId)`（供 M05 路线差价、M09 掉落、M16 图鉴）。
- [ ] 每日事件调度：`daily_random_events`（现 worldpack daily_events 已有雏形）扩量 + 事件触发钩子接口 `onDailyEvent(regionId, eventId)` 供 M08（阵营冲突）/M11（任务钩子）订阅。
- [ ] 生物群系映射：`worldgen_biomes` → 区域与 biome/维度的绑定表（维度 id 由 M13 提供，未合并前用字符串常量）。
- [ ] 旅行路线：`travel_routes_v102` → 区域连通图查询接口（供 M05 trade_routes 差价、M12 NPC 分布）。
- [ ] 灵气地脉挂钩：`SpiritualAuraManager`（BASE_AURA=100，含 5 个已知维度）按 region 参数微调浓度；`LeylineVeinStructure`/`LeylineCompass` 与区域地脉描述对齐。
- [ ] 玩家所在 region 的解析（坐标/维度 → regionId）与登录/跨维度同步（如需新包则走追加 id，勿改旧包）。

## 涉及文件

**语料侧（本模块拥有）**
- `文本材料/data/region_cards/`（23 文件）及发布副本 `src/main/resources/data/seeking_immortals/text_material/region_cards/`
- `文本材料/data/items_by_region*`、`daily_random_events*`、`worldgen_biomes*`、`travel_routes_v102*`

**模组侧（本模块拥有）**
- `worldpack/` 17 类中的区域/每日事件侧：`WorldpackDataService`（regions、daily_events 段）、`WorldpackSavedData`、`SyncWorldpackData`/`WorldpackAction` 包数据面
- `spiritual/SpiritualAuraManager`、`worldgen/LeylineVeinStructure`、`registry/ModStructures`（leyline_vein）
- `LeylineCompassItem`、`SpiritDetectorItem`（区域信息展示）

## 依赖前置库

- Forge worldgen（biome modifier、structure）；`SavedData`（worldpack 状态）。

## 接口交叉（谁提供 → 谁消费）

- **M06 → M07/M08/M09/M10/M11/M13**：`RegionRegistry`（region_id 权威）、每日事件订阅钩子、区域灵气参数。
- **M06 → M05**：travel_routes 连通图（路线差价）。
- **M06 ← M13**：维度 id 注册表。
- **M06 ← M10**：区域刷怪表**数据**由 M10 拥有（spawn_tables 归 M10），M06 只提供 regionId 键。

## 验收与红线

- 23 张 region card 全部可被 `RegionRegistry` 解析并有测试覆盖（结束"零消费者"状态）。
- 每日事件调度必须服务端 tick 驱动、可关闭（config/命令）、不得在客户端做任何裁决。
