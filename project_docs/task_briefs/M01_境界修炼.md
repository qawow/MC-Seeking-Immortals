# M01 境界与修炼基础

- 分支：`task/m01-realm-progression` ｜ worktree：`/root/mc-mod-worktrees/m01-realm-progression`
- 前置模块：M00（数据管线基线）
- 优先级：P0（EXPANSION_ROADMAP 方向 A：境界名对齐等）

## 目标

把语料中的境界推进、灵根、体质、渡劫、种族、鬼修路线等"修炼底座"数据完整落到 `PlayerCultivation` 体系，并对外提供统一的境界/灵根/路线/种族门槛查询 API，供其他所有玩法模块做解锁判定。

## 功能点清单（可勾选）

- [x] 境界名与层数对齐：`cultivation_progression.json` ↔ `Realm`/`RealmStage`/`RealmStageConfig`（当前枚举：MORTAL、QI_REFINING 13 层、FOUNDATION、CORE_FORMATION、NASCENT_SOUL、DEITY_TRANSFORMATION；语料含至真仙的 10 境界表与寿元表）——补齐缺失境界的枚举、寿元、突破参数。
- [x] 灵根体系落地：`spirit_roots.json` + `spirit_roots_catalog` → `SpiritualRoot`/`SpiritRootType`/`SpiritualRootAttribute`/`LingGenCalculator` 的类型与倍率对齐 WORLD_SETTING_BIBLE 灵根表。
- [x] 体质目录落地：`constitution_catalog` → `SpecialPhysique` 扩展（新增体质枚举/数据驱动化二选一，倾向数据驱动）。
- [x] 渡劫规则落地：`tribulation_rules`、`tribulation_items`、tribulation 相关 schema → `TribulationService` + `ThunderTribulationAltar` 行为参数化。
- [x] 突破规则对齐：`realm_breakthrough_v98` → `BreakthroughService`（成功率、失败后果、道具加成）。
- [x] 可选路线：`ghost_cultivation_path.json`（鬼修路线）与 `playable_races.json`（8 可玩种族三层模型入口）→ 在 `PlayerCultivation` 增加路线/种族字段与 NBT 持久化 + 登录同步。
- [x] 对外门槛 API：在 `CultivationHelper`（或新建 `ProgressionGateApi`）提供 `meetsRealm / meetsRoot / meetsPath / meetsRace` 静态查询，供下游模块调用。

## 涉及文件

**语料侧（本模块拥有）**
- `文本材料/data/cultivation_progression.json`（10 境界:QI_REFINING 13 层→FOUNDATION 4→CORE 3→NASCENT 3→DEITY 3(ascension_gate)→VOID→BODY_INTEGRATION→GREAT_VEHICLE→真仙;寿元/spirit_per_sub/tribulation_tier 字段）
- `文本材料/data/spirit_roots.json`（element→methods 门控表）、`spirit_roots_catalog*`（10 元素×5 品阶+单/双/三/变异权重,mortal_awakening_chance=0.08）
- `文本材料/data/constitution_catalog*`（特殊体质:通玉凤髓/龙吟/自治/不灭…,与灵根叠乘帽 x2.5）
- `文本材料/data/tribulation_rules*`（劫类型:waves/damage_per_wave/branch/failure）、`tribulation_items*`、`tribulation_tier_schema*`、`tribulation_master_schema*`（小/大/仙三级+妖兽七阶化形钩子）、`tribulation_narrative_lore*`
- `文本材料/data/realm_breakthrough_v98*`（10 段突破链:requirements/process/base_success/modifiers/fail common+severe）
- `文本材料/data/ghost_cultivation_path.json`、`playable_races.json`、`novel_cultivation_setting_waves*`、`novel_cultivation_learn_requirements_waves*`

**模组侧（本模块拥有）**
- `cultivation/` 包 21 类：`PlayerCultivation`（1808 行）、`CultivationProvider`、`CultivationHelper`、`Realm`、`RealmStage`、`RealmStageConfig`、`SpiritualRoot`、`SpiritRootType`、`SpiritualRootAttribute`、`SpecialPhysique`、`LingGenCalculator`、`BreakthroughService`、`TribulationService`、`MeditationFormula`、`ImmortalAffliction`、`GoldCoreGrade`、`VialGrade` 等
- `block/ThunderTribulationAltar*`（渡劫祭坛行为）
- `command/`（realm/root/breakthrough/affliction 子命令的展示对齐）

## 依赖前置库

- Forge Capability 系统（`CultivationProvider`，attach 点在 `ModEvents.attachCapabilities`）。
- `SyncCultivationDataPacket`（现有包）：若新增境界/路线/种族字段需要同步，**必须**改包字段 → 升 `PROTOCOL_VERSION` + `mod_version`。

## 接口交叉（谁提供 → 谁消费）

- **M01 → M02/M04/M05/M08/M10/M11/M13/M14/M15**：境界/灵根/体质/路线/种族门槛查询 API（功法学习、丹方等级、商店档位、宗门入门、御兽契约、任务门槛、飞升条件、战斗属性推导、法宝认主）。
- **M01 → M14**：境界推导基础属性的输入值（`CombatStats` 从境界取数）。
- **M01 ← M00**：语料同步与校验流程。

## 验收与红线

- `PlayerCultivation` NBT 向后兼容：旧存档字段缺失时给默认值，禁止读档崩溃。
- 寿元/境界表与 WORLD_SETTING_BIBLE 完全一致，不自创数值。
- 红线（DESIGNER_HANDBOOK §5）：突破失败**永不**消耗唯一剧情道具。
