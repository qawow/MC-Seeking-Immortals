# M10 妖兽与生态

- 分支：`task/m10-beasts-ecology` ｜ worktree：`/root/mc-mod-worktrees/m10-beasts-ecology`
- 前置模块：M00、M01（十三阶↔境界映射）、M03（材料掉落 id）、M14（状态 id，可先桩）、M02（效果 id，可先桩）
- 优先级：P1

## 目标

落地约 1850 条妖兽图鉴：十三阶体系、区域刷怪表、掉落材料、灵宠契约与成长、傀儡实体，为秘境（M09）提供 Boss，为区域（M06）提供生态数据。

## 功能点清单（可勾选）

- [ ] 妖兽主数据：`beast_bestiary`（~1850 条）+ `beast_tier_schema` + `thirteen_tier_map` → 数据驱动的妖兽定义服务（属性按 M01 境界映射缩放；先复用/变体化现有实体模型，GeckoLib 建模分批）。
- [ ] 刷怪表：`spawn_tables` + `region_spawn_tables_v98`（现由 `BeastSpawnTableService` 181 行处读取）扩量，键为 M06 region_id。
- [ ] 掉落：`beast_materials_loot_v92` + `beast_loot_tiers` → loot table 生成（材料 id 走 M03 解析）。
- [ ] 灵宠体系：`spirit_beast_companion_v93` + `companion_growth_v99` → `BeastContractService` 契约/成长/口粮（红线：真灵/同伴兽不进日常刷怪表）。
- [ ] 傀儡实体：`puppet_definitions.json` → `SummonedServitor` 变体扩展 + `ServitorRegistrySavedData`（组装配方归 M04，部件物品归 M03）。
- [ ] Boss 供给：秘境 Boss（M09 指定 id 清单）的实体注册、阶段技能（技能引用 M02 效果 id + M14 状态 id）。
- [ ] 图鉴数据出口：击杀/契约解锁的 bestiary 记录（展示归 M16）。
- [ ] `CaptureJar` 捕捉规则与十三阶上限对齐。

## 依赖前置库

- Forge 实体注册/属性/AI goal 体系；GeckoLib（`ModCompat.GECKOLIB_LOADED` 现仅检测——若引入实体动画需把依赖声明升级为强制并在简报更新说明中记录）。

## 接口交叉（谁提供 → 谁消费）

- **M10 → M09**：Boss/守卫实体（按 M09 的 id 清单交付）。
- **M10 → M06**：区域刷怪表数据（M06 提供 regionId 键）。
- **M10 ← M01**：十三阶↔境界映射与契约境界门槛。
- **M10 ← M02/M14**：技能效果 id、状态 id。
- **M10 ← M03**：掉落材料 id。

## 验收与红线

- 刷怪表每条的 beast_id/region_id/掉落 id 全部可解析（校验测试）。
- 红线（DESIGNER_HANDBOOK §5）：**真灵与剧情同伴永不进入日常 spawn table**；十三阶跨带压制规则服务端强制。
- 实体数量控制：区域刷怪必须有 cap 与去重，禁止无上限刷新。
