# 凡人流设定实现大纲

> 来源：外部设定资料汇编（历史 Windows 路径 `D:/浏览器/凡人修仙传_设定资料汇编 (1).md`；本仓库以本文件与 `文本材料/` 为权威）
>
> 用途：后续 AI / 开发者读取本文件，将外部设定资料转化为 `寻仙问道` 的原创实现路线。
>
> 原则：保留“凡人流修仙”的玩法结构，不照搬具体剧情、强绑定人物、专属法宝或独特事件；优先服务当前 Forge 1.20.1 项目的已有系统。

## 1. 设计原则

### 1.1 保留结构，不照搬剧情

可直接借鉴的结构：

- 境界：凡人、炼气十三层、筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫、飞升。
- 核心资源：灵力、修为、神识、肉身强度、走火风险、天劫承受。
- 天赋：灵根、灵根属性、灵根纯度、特殊体质。
- 成长链：打坐吐纳、功法、法术、丹药、法宝、灵脉、秘境、宗门。
- 玩法职业：炼丹、炼器、制符、阵法、御兽、傀儡、拍卖与坊市。

需要原创化处理的内容：

- 不直接复刻具体人物经历。
- 不强依赖原作专属物品名、独特组合设定和剧情强绑定法宝。
- 宗门、秘境、法宝、任务线可以采用相似功能定位，但应使用原创名称和原创描述。

### 1.2 先闭环，再扩内容

当前项目已有系统较多，后续开发应优先把已有系统连成可玩闭环：

- 灵根测试。
- 打坐吐纳。
- 修为增长。
- 手动突破。
- 丹药辅助。
- 走火入魔。
- 技能释放。
- 飞行法宝。
- 炼丹 MVP。
- 神秘小瓶。
- HUD 与技能槽。

在这些系统可稳定贯通后，再扩展宗门、秘境、灵宠、傀儡、拍卖会和高阶境界。

## 2. 推荐实现顺序

### Phase A：MVP 集成与基础闭环

目标：确认玩家从凡人到筑基的核心流程完整可玩。

范围：

- 灵根测试后永久写入资质、属性、纯度和体质。
- 打坐吐纳按灵气浓度、灵根、功法品质、灵石增幅结算修为。
- 修为满额后由按钮、按键或命令手动突破。
- 突破消耗丹药或药力，显示材料、拥有量、成功率和加成来源。
- 突破失败回退修为并增加走火风险。
- 走火风险按轻微、中度、严重、极端四级结算。
- 练气期技能能从绑定槽释放，并有真实效果、消耗和冷却。
- HUD 显示境界、修为、灵力、神识、走火风险和打坐进度。

重点补齐：

- 执行 `docs/task-board.md` 的 Phase 9 MVP 集成测试。
- 补齐筑基期技能：神识扩展、御剑飞行进阶、罡气护体、五行遁术、北斗剑阵、阵法感知。
- 技能正式图标、冷却遮罩、释放反馈。
- 资源加载、物品显示、多人服务端校验回归。

验收标准：

- 新玩家能从测灵根开始自然推进到筑基。
- 灵力不足、冷却未结束、未学技能、空槽释放均被服务端拒绝。
- 关键 HUD 与修仙面板不出屏、不遮挡原版 UI。
- `./gradlew build` 成功。

### Phase B：宗门与新手任务线

目标：把“低资质凡人靠资源和谨慎成长”的新手体验落地。

建议原创结构：

- 山门小派 / 凡俗武馆：新手引导势力。
- 越国六宗：第一批正式修仙宗门。
- 身份阶梯：杂役、外门、内门、真传。
- 门派职能：传功、丹房、任务堂、坊市、执法、禁地入口。

系统模块：

- `Quest`：任务定义。
- `QuestStage`：阶段目标。
- `QuestProgress`：玩家进度，保存到 `PlayerCultivation` 或独立能力。
- 宗门声望。
- 宗门贡献积分。
- 宗门 NPC：执事、传功长老、丹房长老、坊市商人、考核弟子。
- 简单对话系统和任务状态显示。

优先任务线：

1. 测灵根。
2. 入门考核。
3. 领取基础功法。
4. 完成采集或击杀劳役。
5. 炼制第一炉丹药。
6. 收集筑基丹材料。
7. 使用神秘小瓶催熟关键灵草。
8. 尝试筑基。
9. 成为内门弟子。

验收标准：

- 玩家可根据灵根条件加入至少一个宗门。
- 任务阶段可保存、重登后恢复。
- 贡献积分可兑换灵石、丹方、功法卷轴或材料。
- 任务奖励不依赖客户端信任。

### Phase C：炼丹系统升级

目标：把当前炼丹 MVP 升级成长期生活职业。

核心结构：

- 丹炉。
- 丹炉盖。
- 火源：地火、丹火、灵火、雷火。
- 丹方。
- 灵草材料。
- 炼丹等级。
- 成丹品质。
- 废丹与爆炉。

实现内容：

- 新增 JSON 炼丹配方目录：`data/seeking_immortals/recipes/alchemy/`。
- 炼丹等级 LV1-LV10。
- 炼丹经验与升级。
- 丹炉等级。
- 火源等级。
- 丹方物品或玉简物品。
- 炼制 UI：材料槽、丹方槽、火源状态、进度条、成功率、爆炉率。
- 品质判定：下品、中品、上品、极品、废丹。
- 等级错配惩罚：高火低炉爆炉，低火高炉无法炼制。

优先丹药：

- 凝气丹品质版。
- 回灵丹品质版。
- 筑基丹品质版。
- 稳神丹品质版。
- 延寿丹。
- 洗髓丹。
- 补天丹。
- 结丹辅助丹。

验收标准：

- 炼丹配方可数据驱动新增。
- 成丹率受炼丹等级、丹炉等级、火源等级、材料品质影响。
- 失败有明确产物或风险。
- 丹药效果进入统一冷却、药力或增益系统，避免无限叠加。

### Phase D：炼器与法宝系统

目标：把飞剑和飞行法宝扩展成完整装备成长线。

装备分层：

- 法器：练气、筑基阶段常用。
- 法宝：结丹后炼化，可作为本命法宝。
- 古宝：稀有掉落或秘境产出。
- 灵宝 / 仿灵宝：高阶法宝线。
- 仙器：终局预留。

系统内容：

- 炼器鼎。
- 炼器配方玉简。
- 主材 / 辅材。
- 精血祭炼。
- 认主绑定。
- 法宝品阶。
- 法宝灵力储量。
- 法宝主动技能。
- 强化、修复、重铸。
- Curios `artifact` 槽扩展。

优先实现：

- 飞剑品阶。
- 法宝认主后不可被他人正常使用。
- 法宝飞行速度、高度、灵力消耗按品阶和境界共同决定。
- 法宝主动技能：护体、飞剑弹射、短程遁光、剑阵。

验收标准：

- 筑基玩家可用低阶飞行法器。
- 结丹玩家可炼化本命法宝。
- 卸下、灵力不足、死亡、换维、低境界均正确撤销飞行能力。

### Phase E：阵法与符箓

目标：补齐修仙辅助体系，让资源、灵石和地形更有用途。

阵法方向：

- 聚灵阵升级。
- 防御阵。
- 困敌阵。
- 传送阵。
- 禁制阵。
- 灵脉阵眼。
- 洞府护山阵。

符箓方向：

- 火弹符升级线。
- 金甲符升级线。
- 疾行符升级线。
- 避雷符。
- 隐身符。
- 传送符。
- 镇魂符。
- 破禁符。

核心规则：

- 制符需要符纸、朱砂、灵墨、神识。
- 阵法需要阵盘、阵旗、灵石供能。
- 高阶阵法需要布置多个方块或多方块结构。
- 阵法消耗灵石储量或附近灵脉能量。

验收标准：

- 阵法效果服务端计算。
- 阵法有明确供能和范围限制。
- 符箓可消耗品化，效果不绕过技能系统校验。

### Phase F：妖兽、灵宠与材料

目标：让世界探索自然产出修仙资源。

妖兽分层：

- 低阶妖兽：练气至筑基。
- 中阶妖兽：结丹至元婴。
- 高阶妖王：化神以上。
- 稀有灵兽：可驯服或掉落特殊材料。

掉落材料：

- 妖丹。
- 兽骨。
- 鳞甲。
- 灵角。
- 毒囊。
- 精血。
- 羽毛。
- 灵虫甲壳。

灵宠系统：

- 认主仪式。
- 精血契约。
- 忠诚度。
- 成长等级。
- 技能槽。
- 侦查、战斗、采集、寻宝四类定位。

优先灵宠：

- 嗅灵兽：辅助寻找灵草或灵脉。
- 风鹰类灵宠：侦查与标记敌人。
- 防御型灵兽：短时护盾或嘲讽。
- 灵虫群：毒攻、破甲、群体骚扰。

验收标准：

- 妖兽等级和玩家境界匹配。
- 掉落材料进入炼丹、炼器或制符配方。
- 灵宠命令和伤害结算均在服务端执行。

### Phase G：秘境与副本

目标：把“特殊开放条件 + 特殊环境规则 + 分层探索 + 稀有掉落”落成 Minecraft 玩法。

秘境模板：

- 开放条件：令牌、周期、宗门任务、阵法开启。
- 环境规则：高灵气、禁飞、禁传送、毒雾、雷暴、魔气、空间裂缝。
- 探索结构：入口、外围、核心、宝库、Boss 区。
- 掉落：丹方、法宝材料、高阶灵草、秘术卷轴、阵旗、妖丹。

优先秘境：

- 低阶禁地：练气至筑基，高风险采药。
- 古修洞府：筑基至结丹，阵法和机关。
- 魔气山谷：魔化、走火、毒雾和魔兽。
- 灵脉洞天：高灵气修炼区，但有强敌和时间限制。

验收标准：

- 秘境入口有明确条件。
- 资源刷新受限制，避免无限刷取。
- 高灵气收益伴随风险或进入成本。

### Phase H：经济、坊市与拍卖会

目标：让灵石、丹药、法宝、材料形成可控流通。

系统模块：

- 坊市商人。
- 宗门兑换。
- 拍卖会 UI。
- 高阶物品竞价。
- 灵石四级兑换。
- 玩家出售材料。
- 每日或周期性库存。

价格结构建议：

- 日常交易：下品 / 中品灵石。
- 低阶丹药与符箓：下品灵石。
- 高阶丹药和法宝材料：中品 / 上品灵石。
- 拍卖会压轴：极品灵石 + 稀有材料。

验收标准：

- 普通市场和高阶拍卖分离，避免经济被顶级物品打爆。
- NPC 库存和价格可配置。
- 多人服务器下交易由服务端校验物品、数量和货币。

### Phase I：高阶境界与天劫

目标：扩展到结丹、元婴、化神及以后。

境界重点：

- 结丹：金丹品质、本命法宝、丹火。
- 元婴：元婴出窍、第二元婴、夺舍规则、神识大幅提升。
- 化神：天地灵气调用、飞升灵界前置。
- 炼虚：五行合一、人造灵根或补全五行。
- 合体 / 大乘：法则感悟、大天劫、飞升准备。

天劫系统：

- 小天劫。
- 大天劫。
- 飞升劫。
- 心魔劫。
- 五行之劫。
- 真雷劫。
- 雷劫抗性。
- 避雷符 / 御雷法宝。
- 渡劫失败惩罚。

验收标准：

- 天劫不是纯随机秒杀，应允许玩家提前准备。
- 天劫强度受境界、次数、功法、环境、法宝和天劫承受影响。
- 高阶境界需要新资源、新地点和新风险共同支撑。

## 4. 版本与构建规则

- 本文件为设计文档，不直接要求 `mod_version` bump。
- 如果后续按本大纲修改 Java、资源、数据包、构建逻辑或 gameplay/config，需要先递增 `gradle.properties` 的 `mod_version`。
- 如果修改网络包字段、顺序、编码或不兼容通道行为，需要同时 bump `ModNetwork.PROTOCOL_VERSION`。
- 每次代码、资源或数据包变更后必须运行 `./gradlew build`。
