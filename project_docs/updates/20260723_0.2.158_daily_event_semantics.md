# 0.2.158 每日事件运行时语义

## 变更类别

代码、资源、本地化、测试与项目文档更新。上一批作者丹药/消耗品视觉档案已提交为 `0.2.155`；`0.2.157` 成功指纹早于并行提交最终收录的可发布源码复核修复，因此最终将 `mod_version` 协调至 `0.2.158` 并重新构建。

## 作者目录与调度

- 新增 `DailyEventEffectCatalog`，无损加载 `daily_random_events.json` 与 `tianyuan_daily_events.json` 的 76/76 条作者事件。
- 保留标量 `effect/buff/debuff/spawn`、数组 `effects/hooks`、对象 `effects`、未知字段、奖励占位、地域、境界、势力战、作者时长与小数权重；未知语义失败关闭但不丢失。
- Scheduler 以 1000 倍固定点保存作者小数权重，支持 `tiannan_border`、`mulan`、`great_jin`、`wild_land`、`diyuan` 到运行时地域的别名投影，并让作者定义覆盖旧 worldpack 的同 ID 条目。
- `Realm.fromDesignId` 接受作者 `VOID_REFINING`，未知境界仍失败关闭。

## 生命周期与成长

- `PlayerCultivation` 新增每日事件专属修炼倍率，与药物/消耗品 `CultivationBoost` 分开保存、相乘和清理；作者 1.1/1.2 倍事件不再污染普通增益。
- `breakthrough_chance_small` 通过独立 event bonus 进入突破公式，不写入丹药辅助状态，也不改变辅助材料判定。
- 登录、重生、跨维、跨日、每秒续期和配置关闭均由服务端刷新；到期判定统一为 `now >= until`，客户端倒计时归零后不再显示旧事件。
- realm gate 在作者效果、遭遇和跨服务读取前校验；越级事件只保留事件身份，不发放倍率、突破或危害。

## 遭遇、势力与渡船

- 每日遭遇锁由无限增长的逐 ID 布尔键改为 `(region,event,until)` 有界记录并迁移旧布尔锁；和平模式或零实体成功时不落锁，任一实体成功即锁定本轮，三类生成不会因部分成功后重试而突破作者数量，灵兽额外禁用灵脉簇加成。
- 作者 `faction_war` 优先于随机冲突匹配；慕兰侦察、边巡、魂阵补给、天南军功集结及旧 `mulan_tianlan_campaign` 候选均归一到 `mulan_tianlan_war_outbreak`，并从 `war_ref` 读取 `tiannan_alliance` 对 `mulan_fashi`。相同势力对可合并最多 32 个地域/维度 scope，NBT 保留旧单 scope 镜像；冲突记录保存地域、阶段和作者期限，空事件会清空且绝不参与子串匹配。
- `FerryTravelPolicy` 在任何票据、阴石、贡献、空间节点预留、实体创建或载具燃料消耗前刷新当前地域并执行封航。
- 真实渡船范围包括冥河往返阴冥、天南往返乱星海、乱星海往返外海坊市、作者 `sea_ship` 以及显式 ferry/ghost-boat/spirit-boat/pocket-gate 路线；私人 `flying_boat` 不受渡船规则影响。
- `chaotic_sea_pirate_raid` 可把单张 `spirit_boat_ticket` 或渡船载具燃料翻倍；`chaotic_sea_blockade` 的冲突 `ferry_delay=true` 会阻止出行。法宝绑定载具在临时封航时不再错误退化为免费移动增益。

## 经济与展示边界

- 作者灵草涨价/折扣与 `tax_mult` 接入现有市场结算，宗门贡献加成只影响贡献奖励；`merit_mult_2` 不再误乘普通宗门贡献。
- Worldpack UI 为修炼、突破、贡献、功勋、价格、税、渡船、环境危害、遭遇和任务机会提供分组文本。
- `merit_mult_2`、`inverse_star_smuggle_chance`、`star_palace_patrol_bonus` 当前没有权威生产结算调用者，目录覆盖状态明确为 `PRESERVED`。纯函数/原始值仍保留，后续必须接入真实奖励、走私和巡查事务后才能提升为 `EXECUTED`。

## 剩余风险

- 自动测试不替代客户端、专服和多人实机验收；跨日、重连、跨地域、多人遭遇密度、封航提示、船票/燃料平衡仍需人工检查。
- 事件仍以玩家当前地域的服务端 roll 为权威；从其他地域驶入目标封锁区的跨区政策目前不会预读目标地域事件。
- 功勋奖励、逆星走私概率、星宫巡查奖励仍是无损保存的作者信号，不是已完成玩法。
