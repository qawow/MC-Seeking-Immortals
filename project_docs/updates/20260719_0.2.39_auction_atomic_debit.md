# 0.2.39 拍卖余额不足扣款原子性

## 范围

本批只修复拍卖出价余额不足时的部分吞款，不改拍卖价格、竞价阶梯、共享榜、个人 escrow、结算奖励或退款 schema。

## 根因

`AuctionSoftService.consumeShards` 在确认总余额前逐格 `shrink`。当多个碎片栈的总数小于本次 `delta` 时，方法返回 `false`，但先扫描到的碎片已永久扣除，竞价、escrow 和声望均未提交。

## 实现

- 将库存引用收集后交给两阶段匹配扣除核心，并按对象身份去重，防止异常重复引用被重复计价。
- 第一阶段只读取匹配栈数量并使用 `long` 汇总；不足时立即返回且不调用任何消费动作。
- 第一阶段同时快照每个唯一匹配栈的可用数量；第二阶段仅在总额充足后按快照跨栈扣除，精确消费请求数量并保留非目标栈。
- 核心仅对零请求幂等成功；负数、空列表、空匹配器、空计数器或空消费器均 fail-closed。

## 测试

- 跨两个目标栈但总额少 1：返回失败，两个目标栈与中间非目标栈数量完全不变。
- 跨两个目标栈且总额充足：返回成功，第一栈清空、第二栈只扣余量，非目标栈不变。
- 同一目标栈引用重复出现：只计一次，余额不足失败且原栈不变。
- 负数请求：失败且原栈不变。
- 首次使用真实 `ItemStack` 的纯 JUnit 夹具因 Minecraft registry 未 bootstrap 失败；改为不依赖游戏注册的可变计数夹具后，`AuctionSoftServiceTest` 4 项 BUILD SUCCESSFUL（13s）。

- max 复核指出重复引用与负数请求边界；补丁后的 0.2.39 定向 `AuctionSoftServiceTest` 6 项 BUILD SUCCESSFUL（13s）。
