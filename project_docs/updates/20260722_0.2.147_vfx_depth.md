# 0.2.147 Lodestone 全域 VFX 深化

## 范围

本批在既有 Lodestone `1.20.1-1.6.4.1` 基础上深化术法、阵法、法宝、炼器、工站、召唤物与天劫视觉，不引入第二套视觉运行库，不改变权威伤害、目标选择、消耗、冷却或结构判定。

## 实现

- 客户端将视觉意图拆为 anticipation、release、sustain、afterglow 四阶段，使用受限的 additive/lumitransparent 粒子、depth fade、extruding spark、世界光束/轨迹和位置震屏；距离 LOD、低粒子设置、每 tick 粒子/震屏预算与活动事件上限共同限制开销。
- 区域、目标、阵法与剑阵术法复用真实服务端命中几何；投射物由客户端跟踪轨迹，服务端只发送命中/消散终结事件。召唤物覆盖生成、周期状态、命中与最终移除。
- 活跃增益/减益绑定实际 MobEffect。SelfBuff 以 `(player, semantic, effectId)` 区分来源，以 `(player, family, motif)` 合并可见状态；只在同视觉最后一轨结束时消散，重施会取消尚未发送的旧消散。
- SelfBuff 登出时冻结并持久化不超过原施法边界的剩余 tick，登录后再与实际 MobEffect 剩余时间取最小值。STATUS 与 DISSIPATE 全服各最多 16 包/tick，待发队列各最多 512；同一逻辑 tick 重入不重复 drain。
- 阵法视觉每维每 tick 最多发送 48 包，待发上限 384；即使当前无活动阵法也继续排空待发队列。法宝激活/炼制、工站运行和天劫阶段使用同一语义 family/motif 协议。
- 资源驱动 buff/movement 将作者 `technique.id()`、`spec.type()` 和 `spec.element()` 注入 SelfBuff，不再统一继承虚拟 FIREBALL/FIRE 语义。

## 真实边界

- 92 个设施中只有 34 个具备真实 validator，58 个仍不可形成；VFX 接线不会把不可形成设施伪装为已实现玩法。
- 法宝语义映射契约验证分派，不证明每个目录物品都可正常获取或到达激活路径。
- 约 74 个直接载体中 73 个进入激活服务；储物手镯按设计走专用存储流程并绕过激活服务。
- 自动测试与启动烟测不能替代人工视觉验收。多人密集粒子、透明排序、低粒子设置、跨维度迁移、长时状态和普通生存可达路径仍需实机签字。
