# 0.2.265 M-C 旧命名 NPC 迁移（M 系列收口）

## 更新内容

把旧世界里「靠命名牌识别 NPC」改成「一次性迁移到持久 id」。

### 核心缺口

`handleLegacyNamedVillagerInteraction` 此前只读 `getCustomName()`：没有持久 id、没有区域校验、没有迁移闩。

给任意村民挂一块写「墨老先生」的命名牌，就能**反复、在世界任意位置**触发 `SevenMysteriesQuest.start` 加一次免费灵根测试（`LingGenTestStoneItem.testPlayer`）。这是伪造向量，不是兼容路径。

### 迁移窗口

新增 `LegacyNpcMigrationService`。窗口要求五条同时成立：

- 无持久 id
- 已知旧实体类型
- 合法作者名
- 匹配区域
- 未处理过

`isMigrationCandidate` 写成纯布尔函数，可以脱离服务端测试；任意一条不成立窗口就关闭。首次交互把 `SeekingImmortalsNpcId` + `MigrationVersion=1` + `SourceRegion` + `MigratedAt` 写进实体 persistentData，之后只读持久 id。

### 伪造拒绝

名称**精确匹配**，没有前缀或子串匹配 —— 「墨老」「墨老先生的徒弟」都不通过。合法名字但区域不符，同样判为伪造。拒绝结果闩到 `TAG_REJECTED`，同一块命名牌不会每次右键都重新评估一遍。

### 区域权威的来源

查证时发现这六个别名 id（`npc_mo_lao`、`npc_text_quest_guide`、`npc_mulan_envoy`、`npc_yinluo_steward`、`npc_star_palace_broker`、`npc_kunwu_steward`）**在整个数据树里都不存在**。它们的唯一权威是 `TextQuestChainService.npcFor(chainId)` 的关键字规则。

所以 `legalRegionsFor` 由绑定该 NPC 的任务链 `region` 字段反推：墨老先生=`tiannan`、木兰使者=`mulan`、星宫掮客=`chaotic_sea`、昆吾执事=`dajin`/`kunwu`、阴罗执事=`dajin`/`yinming`/`yinyang_ku`。空集必然拒绝，不会误放行。

### 七玄门执事的纠正

原代码把「七玄门执事」和「墨老先生」都送进同一个 `handleSevenMysteriesNpc(name)`。但 `npcFor` 会把所有含 `qixuan` 的链映射到 `npc_mo_lao`，所以新 id `npc_qixuan_steward` 没有任何链绑定 —— `legalRegionsFor` 会返回空集，导致它永远无法迁移。

查实 `qixuan_men` 与 `huangfeng_valley` 两张宗门卡的区域都是 `tiannan`，加 `PINNED_REGIONS` 显式兜底。

### 邻近校验收口

`isNearBoundNpc` 的 Villager 分支此前同样只比对命名牌 —— 把一个伪造村民放在身边，就能满足所有「与绑定 NPC 对话」的步骤门禁。现在只信 `persistentNpcId`。

### 审计命令

新增 permission 2 的 `/seeking_immortals npc audit`：48 格半径内报告已迁移 / 重复 / 已拒绝 / 待迁移四类，**只读不删**（测试断言 audit 方法体内不含 `discard` / `remove` / `kill`）。

### 收尾时发现的同类漏洞

专用 NPC 路径有完全相同的问题：`handleNamedNpcInteraction` 读 `npc.getCustomName()` 分派，把一个已存在的 `CultivatorNpcEntity` 改名成「墨老先生」也能拿免费灵根测试。

根因是 `spawnQuestNpc(player, name)` 传的 `namedNpcId` 是空串 —— 管理员生成的墨老先生只有显示名、没有 id，所以当初只能按名字分派。现在生成时经 `npcIdForLegacyName` 盖上权威 id，交互改为 **id 优先**；只有 `namedNpcId` 为空的旧档实体才回退显示名，因此已生成的旧 NPC 不会回归。

## 剩余风险

- 旧档中**盖章之前**生成的专用 NPC（`namedNpcId` 为空）仍走显示名回退，对它们改名的向量没有关闭。新生成的一律免疫，但旧实体需要重新生成才彻底干净。我保留这条回退是为了不让已有存档的墨老先生失效。
- `isMigrationCandidate` 的 `knownLegacyType` 参数在 `resolveNpcId` 里硬传 `true`（那条路径只接 `Villager`）。参数已就位，但目前没有第二种旧实体类型需要辨别，所以这一条实际上还没被真正使用。
- `audit` 的 ambiguous 只统计半径内同 id 的重复实体，不检测跨维度重复。
- 迁移是一次性的（按设计），所以在错误区域被误迁移的村民无法自动纠正，只能手工处理，且当前没有解绑/重置命令。
- 六个别名 id 的合法区域依赖 `npcFor` 的关键字规则。如果以后新增任务链的 id 恰好含 `yin`、`star` 等关键字，它的区域会自动成为对应 NPC 的合法迁移区域 —— 这是数据驱动的好处，也是隐式耦合。
