# 0.2.209 轮廓预算调度与跨帧完整性

日期：2026-07-28
`mod_version`：0.2.208 → **0.2.209**；`ModNetwork.PROTOCOL_VERSION` 保持 **30**。

## 问题

作者视觉程序继续遵守每层最多 8 粒和单事件 7/16/30 粒上限，但旧轮廓 helper 按调用顺序消耗预算。首个高采样圆环或线段会取走全部层配额，后置的眼、翼、尾焰、鼎足、头环和星芒长期无法出现；多份具名对象也可能被第一份复杂轮廓独占。

## 修正

- 新增纯 Java `VfxBudgetPlan`，将最多 72 份具名 copies 做均匀空间抽样，并随事件帧推进抽样相位；连续相位可覆盖全部命名位置。
- 每个抽中的副本通过独立子预算渲染。当前副本未用完的配额返回父层，复杂第一份不再挤掉其余副本。
- 将强轮廓拆成核心与细节组件：预算允许时核心至少获得两个完整区间样本，细节按相位轮转，低粒子档也能在连续演出中补齐识别特征。
- 29 处 helper 接入组件调度，覆盖原有强形象和全部 18 种 `semantic_layers_v3` 层内形象。
- `shortLine`、`ring`、`rotatingRing`、`verticalRing` 与 `helix` 改用预算感知的全区间采样；只有 1-3 粒时也会跨越整段或整圈。

## 边界

- 未提高 MINIMAL 7、DECREASED 16、ALL 30 的单事件上限。
- 未改变 `ClientVisualEngine` 每 tick 总预算、公平事件轮转、最多 8 粒的层配额或视觉包协议。
- 目录仍为 `semantic_layers_v3`，作者术法 2,292 profiles、统一视觉目录 5,727 profiles。

## 验证

- `VfxBudgetPlanTest`：固定 72 份对象在 18 个相位内完整覆盖、核心优先和低预算轮转。
- `LodestoneVfxContractTest`：固定副本子预算、组件调度、稀疏全区间采样和 7/16/30 上限。
- 定向 Gradle 测试：通过。
- 最终 `./gradlew build --no-daemon --max-workers=1`：`BUILD SUCCESSFUL in 1m 23s`；1,167 项测试，failure/error/skipped 均为 0。
