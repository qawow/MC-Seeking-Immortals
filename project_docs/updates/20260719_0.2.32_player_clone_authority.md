# 2026-07-19 0.2.32 玩家死亡 Clone 与护送事务

## 范围

修复玩家死亡或 End 返回时永久账本丢失、极端走火保留物滞留/重复策略，以及进行中宗门护送实体无法跨 Clone、维度或区块生命周期恢复的问题。

## 实现

- 新增 `PlayerPersistentDataClonePolicy`，集中调用 11 个既有深拷贝 helper，并复制 39 个固定永久键与 `boss_spawned_`、`daily_spawned_` 两个动态前缀，共覆盖 58 个永久根键。
- Clone capability 复制置于 `reviveCaps()` 后的 `try/finally`，无论任一复制步骤是否异常都失效原玩家 capability；对话 session、飞升 pending/backup、秘境 session latch、飞行/术法、短时药效和护送实体 UUID 明确不复制。
- 极端走火以 `LivingDropsEvent` 作为已越过可取消死亡门的提交信号；首次伤害未提交时回血后尝试 fallback kill，仍未提交或抛错则在 `finally` 回滚隔离半包，不再用生命值猜测死亡是否成立。
- 旧极端 payload 在下一次极端走火前先恢复；有效 compound list 深拷贝并随死亡或 End Clone 迁移，错误类型清理；重生通过统一 `InventoryDeliveryService` 交付并一次消费。隔离半包始终恢复，不读取可在死亡界面变化的 keepInventory；规则稳定开启时原版可额外保留另一半。
- 玩家/妖兽死亡计分、Boss/秘境奖励、飞行清理、秘境死亡和渡劫结算从可取消的 `LivingDeathEvent` 移至 post-cancellation `LivingDropsEvent`，取消死亡不再提前提交副作用。
- 护送完成凭证跨死亡和 End 保留；进行中护送在 Clone 清旧实体、Respawn 或普通跨维后重建。生成失败写 pending/退避时间并每秒重试，不再删除 generated mission、进度或 capability 任务。
- 护送生成在 `addFreshEntity` 后同步写入 `ServitorRegistrySavedData` 并检查并发上限；清理按全维度 UUID 查找，registry 缺行也写 dismissed tombstone，使未加载旧实体稍后注册时立即销毁。
- 护送 tick 区分当前维度暂时卸载与真实丢失/跨维；暂时卸载保留绑定，真实丢失进入重建，避免永久卡死或重复实体。
