## 下一批最高优先级

### P0：秘境与 Boss 没有 owner-session 奖励归属

`SecretRealmTrialService` 只在试炼实体写 `Kind/Realm`，`BossEncounterService` 只写 `BossId`，死亡回调按实际击杀者直接结算。其他玩家可击杀发起者生成的实体并拿走首通、宝箱、声望和清关，而发起者的生成标记已经消耗。

- 涉及：`worldpack/SecretRealmTrialService.java`、`worldpack/BossEncounterService.java`、`event/ModEvents.java`。
- 修复方向：实体和密封箱携带 `OwnerUUID`、`SessionUUID`、`RealmId`；奖励以 encounter UUID 在 SavedData 原子 claim，再按匹配活动会话幂等交付。
- 回归：跨玩家击杀拒绝、同 owner 重放拒绝、重登/重启后同一 encounter 只结算一次、掉落实体拒绝生成时仍可恢复。

### P1：C2S 菜单动作缺少服务端现场授权

`ShopActionPacket`、`AuctionActionPacket`、`SectActionPacket` 没有核验当前菜单、容器来源、距离、维度或 NPC/方块上下文；相关 menu 只验证玩家存活。修改客户端可在任意位置发起公开商店购买、竞拍/结算或宗门动作。

- 涉及：`network/ShopActionPacket.java`、`network/AuctionActionPacket.java`、`network/SectActionPacket.java`、`menu/MarketHallMenu.java`、`sect/SectContributionService.java`。
- 修复方向：菜单保存服务端来源上下文；动作统一验证 `containerMenu` 类型、目标 ID、维度、距离和会话 nonce；普通命令入口复用相同 guard，诊断命令仅保留 permission 2。
- 回归：无菜单、错误菜单、跨维、超距、伪造 shop/sect ID、关闭菜单后重放均失败。

### P1：拍卖付款、结算和退款缺少事务边界

余额不足时 `consumeShards` 会先缩掉现有全部碎片再返回失败；结算路径在交付与 `settled/won` 写入之间可崩溃或抛错，产生重复奖励或永久丢失。离线退款也没有可确认的交付账本。

- 涉及：`catalog/AuctionSoftService.java`。
- 修复方向：先完整预检再扣款；为 bid、claim、refund 引入持久事务 ID 与 `pending -> delivered` 状态；余量无法落地时保留 pending，后续登录重试。
- 回归：余额不足零扣除、重复包/重复登录、交付中断、库存满、物品实体拒绝加入世界、服务器重启。

### P1：统一物品交付仍有丢失/重复窗口

`InventoryDeliveryService.giveOrDrop` 不返回交付结果，也不检查掉落实体 `addFreshEntity` 是否被世界拒绝。极端走火 payload 一次性删除后才解析和交付；若第 N 项异常或 NBT 损坏，后续条目无法恢复。多个奖励调用点分别采用“先交付后记账”或“先记账后交付”，二者在异常/重试时分别可能复制或丢失。

- 涉及：`item/InventoryDeliveryService.java`、`persistence/PlayerPersistentDataClonePolicy.java`、`cultivation/BreakthroughService.java`、`catalog/AuctionSoftService.java`、`quest/QuestRewardService.java`、`quest/TextQuestChainService.java`、`worldpack/SecretRealmTrialService.java`、`artifact/ArtifactStorageService.java`、`worldpack/BossEncounterService.java`、`worldpack/AscensionService.java`。
- 修复方向：交付 API 返回插入、掉落成功和待交付余量；所有永久奖励采用持久 outbox/claim ID；极端 payload 先完整序列化校验，再移除槽位，并逐条消费/隔离坏条目。
- 回归：满背包、`addFreshEntity=false`、动态异常堆叠、畸形 NBT、交付第 N 项抛错、重启和重放。

### P1：任务 hook 可跳过当前步骤

当前击杀、拾取、合成、对话和秘境 hook 只要命中任意链条的 hook 就推进；没有校验当前步骤是否期待该 hook，也缺少目标实体/物品/秘境参数匹配。共享 hook 还可以同时推进多条链。

- 涉及：`quest/QuestHookRuntime.java`、`quest/TextQuestChainService.java`、`data/seeking_immortals/text_material/quest_chains.json`。
- 修复方向：保留 `chain -> ordered steps`，按当前步骤做精确 hook 和 context 匹配，删除“没有明确任务则推进首条活动链”的回退。
- 回归：提前完成、错误实体/物品、两条链共享 hook、完成链、重登后恢复。

### P1：捕捉罐可以移除 Boss/试炼实体

捕捉判断接受任意带 `seeking_immortals_beast_id` 的实体；Boss 也写该键。成功捕捉直接 `discard()`，绕过死亡、奖励和清关，还可能把 Boss ID 作为可释放/契约对象。

- 涉及：`item/CaptureJarItem.java`、`artifact/ArtifactCaptureService.java`、`beast/BeastBossService.java`。
- 修复方向：集中可捕捉白名单，拒绝 Boss、试炼、NPC、他人随从、真灵和非生态实体；要求明确 `tameable`、生态标识和残血阈值后才写罐并移除实体。
- 回归：Boss/试炼/NPC/他人随从拒绝，合法生态兽残血捕捉一次成功，失败不消耗或移除目标。
