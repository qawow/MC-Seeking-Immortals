# 0.2.259 Y-A-2 层刷怪消费者、spawn id 纠正与付代价绕行

## 更新内容

Y-A 收口批，三件事：让 `LayerDef.spawns` 从死数据变成活数据、纠正确定可验证的悬空 spawn id、实现作者的「付代价绕道」分支。

### 1. 层刷怪消费者（逐条 fail-closed）

新增 `SecretRealmLayerSpawnService`，在秘境进入时消费作者的分层名录：

- `resolveRoster(LayerDef)` 逐条解析 spawn id → 图鉴条目；解析失败的条目返回 `resolvable=false` 且 `beastId` 为空，**绝不替换成别的妖兽**，并记 warn 日志。整层无法解析时该层不贡献任何生成，不阻塞其余层。
- 无会话预算可复用（`Session` 只有时限/并发/一次性闩锁），因此自设上限：`MAX_LAYER_SPAWNS_PER_REQUEST=4`、`MAX_LAYER_SPAWNS_PER_ENTRY=10`，参照 `BeastSpawnTableService.MAX_SPAWN_PER_REQUEST` 的既有惯例。
- 按 `session|realm|trial:layer:<id>` 闩锁，重进同一会话不叠加编队。
- 生成体经 `SecretRealmTrialService.tagTrial` 绑定会话归属，击杀门与既有巡逻同规则（非归属者无法领取）。
- 等级取作者层 `threat` 波段与图鉴 tier 的较大值，经 `BeastTierService.scaleStats` 换算血量/伤害，精英不会被层波段拉低。

### 2. spawn id 纠正（21 处，全部可验证）

作者图鉴本就有成套的按层命名族，运行时层却写了从未匹配的临时名。属**数据纠正**，非新增条目，故不影响 BEAST 计数基线：

|---|---|---|
| yinyang_ku | 8 | `silver_wing_yezha`→`yinyang_yezha_adult`（habitat 银翅夜叉巢）、`yin_zhi_horse`→`yinyang_yinzhima`（habitat 阴芝马栖息层） |
| tianlan_secret_grotto | 5 | `wind_blade_wolf`→`tianlan_wind_blade_wolf` |
| void_palace / thousand_bamboo / guanghan | 各 2 | `seal_spirit`→`xutian_seal_spirit`、`crossbow_puppet`→`qianzhu_crossbow_puppet` |
| kunwu_mountain / nether_river_land | 各 1 | `vault_spirit`→`kunwu_vault_spirit` |

全包可解析率 **29/178 → 50/178**；阴阳窟 **0/11 → 8/11**，四个战斗层全部至少有一条可刷。

### 3. 付代价绕行（`pay_yezha_toll`）

作者只有散文没有实现（`{"id":"pay_yezha_toll","when":"向夜叉巢绕路/献祭绕行","effect":"耗资源避战"}`，且流程第 1 步写明「过夜叉巢**或付代价绕道**」）。新增 `SecretRealmBypassService`：

- 仅作者标注的可绕层放行（当前 `yinyang_ku:yy_yezha`），其余 fail-closed。抓马层 `yy_yinzhi` 是目标本体，明确不可购买。
- 事务顺序固定：校验会话/层 → `InventoryReservation.consume` 原子预留（12 枚金灵石，不足则回退 25 点贡献并走 check-then-spend）→ 记账 → 抑制该层名录 + 清场。记账被拒则两条支付路径都退款。
- 绕行合法结算 step 1 的 `ENCOUNTER_CLEARED(region=yy_yezha)`（经 `yinyang_ku:mid` 路由）——否则该分支是死路。绕行**不发战斗战利**，清场不给击杀credit。
- 同会话重复绕行返回 `ALREADY_BYPASSED`，不二次扣费。
- 新 effect type `sacrifice_bypass` + 专用 handler `DialogueWorldActionService.sacrificeBypass`，空 realm/layer 意图拒绝。
- 新作者对话树 `tree_yinyang_toll_broker`（台词取自作者「鬼道散修：夜叉巢？你是送药，还是送菜？」），进入秘境时于锚点旁放置巢口经纪 NPC，**全程不需管理员命令**，满足 Y 系列验收门。
- `SecretRealmSessionService` 新增 `boundEncounterId`，镜像既有 `boundRealmId`，供层级清场过滤自己的生成体。

## 计划偏差（重要，已核实）

计划的「全包机械修正 35 处」不成立。按真实解析语义（id → display → 模糊压缩三级回退）重测：全包 178 条 spawn 仅 29 条可解析，**149 条悬空**，其中纯前缀可机械验证的只有 14 处，habitat 池仅能覆盖 70/167，**20 层零候选**。`void_palace`、`jiuxian_seclusion`、`ancient_cultivator_ruins`、`seven_meridian_cave` 整realm无映射目标；`bf_outer_mist` 有 4 个悬空 id 但池里仅 1 个候选，无法判定各自归属。硬做等于凭空编映射，错了表现为静默刷错怪。故本批只做 21 处可验证纠正，其余 128 处**必须由作者定夺**，不猜。

正因如此，消费者设计为逐条 fail-closed：现在就能上线（50 条可用），id 纠正成为可增量推进的改善，而非消费者的前置阻塞。
