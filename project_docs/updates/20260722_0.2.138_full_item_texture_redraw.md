# 0.2.138 全量物品贴图重绘

## 更新内容

- 新增确定性 `scripts/generate_item_textures.py`，读取当前 bulk 目录和 v118/v120/v122 视觉资料，按类别、元素、稀有度、名称语义和显式覆盖生成物品像素图。
- 重绘 `textures/item` 下全部 1,704 张 PNG，统一为 16x16 RGBA 透明背景；新增 `green_liquid_drop.png` 与 `palm_heaven_bottle.png` 两张原先缺失的同名图。
- 修正 36 个物品模型的共享别名引用。1,590 个直接 `layer0` 模型现全部指向同名纹理；54 个 block-parent item model 保持现有方块模型路径。
- 为掌天瓶、绿液、阵盘、祭坛、界门、钟、剑和罗盘等高置信误判加入显式视觉类别/轮廓，避免目录行为分类或子串规则覆盖真实外形。

## 验证结果

- `python3 scripts/generate_item_textures.py --check`：1,704 张图，坏图 0、尺寸/模式问题 0、透明角问题 0、重复像素组 0、确定性重渲染差异 0、唯一性补丁 0；非透明覆盖率范围 0.363-0.754。
- 模型 JSON 审计：1,644 个 item model 全部可解析；1,590 个直接引用全部同名，缺图 0；54 个 block-parent 父模型缺失 0。
- 视觉 contact sheet 抽检已覆盖 artifact、block item、consumable、currency、equipment、manual、material、pill 与 talisman 分类。
- 共享树首次 `./gradlew build` 在并行 VFX 新包落盘期间暴露两个旧测试基线；协议/方向测试对齐后最终 `./gradlew build` `BUILD SUCCESSFUL in 1m 31s`，871 项测试、0 failures/errors/ignored。
- 提交前收口复验时，普通 `./gradlew build` 因并行 VFX 批次已在同一 `mod_version=0.2.138` 下写入成功 fingerprint、随后又变更 shippable 文件而被 preflight 拒绝；为避免把外部 VFX 批次混入本物品提交，明确使用手工共享树例外 `./gradlew cleanTest build --no-daemon -PaiSkipVersionBumpCheck=true`。清理一次残留测试报告后 `BUILD SUCCESSFUL in 1m 11s`；该 override 仅处理同版本并行批次的 fingerprint 冲突，不替代本批已完成的 `0.2.137 -> 0.2.138` 版本递增。

## 版本与协议

`mod_version=0.2.138`。本批只修改物品资源、模型路由、生成脚本和文档，不改变网络包字段、顺序、类型、注册或频道行为，提交内 `ModNetwork.PROTOCOL_VERSION` 保持 `26`。并行 Lodestone/VFX 的协议 27 工作不属于本提交。

## 剩余风险

- 1,590 个直接图标约使用 111 种二值 alpha 轮廓；逐像素唯一不代表每个物品都拥有完全独立的手绘构图，丹药、典籍、符箓和通用材料仍有同族模板感。
- 64 张名称含 `placeholder` 的兼容图和未引用的 `spirit_stone_superior.png` 继续保留；49 张同名 item PNG 对应 block-parent 模型但不作为直接 `layer0` 使用。
- 仍需真实客户端 inventory、不同 GUI scale、语言环境和第三方资源包覆盖下的最终视觉签字。
