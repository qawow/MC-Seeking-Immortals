# 0.2.261 Y-C 窟外协作炼丹（Y 系列收口）

## 更新内容

### 先纠正两处我上批的错误判断

1. **step 3 并非「因 station 不可达」**。`ItemCatalogService` 把 `alchemy_furnace_g1/g2/g3` 全部别名到 `alchemy_furnace`（g4/g5 没有），所以任何 3 阶及以下丹炉本就满足路由的 `station: alchemy_furnace_g3` 证明。Y-B 更新说明里「step 3 结构性不可达」的结论是错的。
   真实缺口是：**step 3 与阴芝马毫无绑定** —— 随便炼一炉丹去收，就能过这一步。
2. **「储物法器内活体不降级」的风险不成立**。全仓搜索确认本模组没有末影箱接入，也没有任何储物法器/储物戒系统。真实缺口更窄：Y-B 只 tick 背包主格，**副手与盔甲位**的载体永不超时。

### 培婴丹归属：复用而非新注册

用户此前选择「新注册独立培婴丹物品」。实施时发现四处作者源已一致认定 `nascent_soul_pill` **就是**培婴丹：

- `catalog_bulk_items.json` 描述 `目录载体：培婴丹`
- `catalog/pills_index.json`：`"id": "nascent_soul_pill", "display": "培婴丹"`
- `zh_cn.json`：`item.seeking_immortals.nascent_soul_pill` = `培婴丹`
- `catalog/alchemy_recipes_index.json`：`recipe_nascent_soul` 显示「培婴丹方（残篇）」，输出 `nascent_soul_pill`

即 `peiying_dan -> nascent_soul_pill` 别名是作者语义的正确表达，不是兼容性凑合。新注册独立物品会让创造模式页签与 JEI 同时出现**两个都显示「培婴丹」**的物品。故本批改为复用既有载体、保留别名，已在回复中向用户说明并请其确认；若坚持独立物品，可另起一批切换（改动面可控）。

### 协作配方

新增 `alchemy/recipes/peiying_dan.json`（manifest 126→127）：`required_furnace_tier=3`、`ideal_fire_tier=3`、`success_rate=0.15`（作者带下界作基线）、主料 `live_beast_carrier`×1 + `yin_essence_ore`×2 + `spirit_beast_bone`×1，`min_control_realm=CORE_FORMATION`。作者的 tier-5 残篇配方 `nascent_soul_pill` 原样保留 —— 一丹两路（残篇 5 阶 10%，阴芝马协作 3 阶）。`live_beast_carrier` 此前不是任何配方的材料，故 `findByHeldIngredient` 的首个匹配不存在歧义。

### 活体成丹分档

`PeiyingCoopAlchemyService.resolveSuccessRate` 是纯函数，活体与劣材占**互斥子带**：

- 活体 `[0.20, 0.35]`（作者「约两成上下」为下界）
- 劣材 `[0.15, 0.18]`

因此任何站点等级、炼丹技能、灵脉或协作人数都无法把「打折的肉」抬到活体水平，而 `[0.15, 0.35]` 是硬上下界。载体状态在 `consumeInputs` **之前**按 `inventory.items` 同序快照 —— `AlchemyRecipeService.removeItems` 取首个匹配，快照若不同序就可能描述另一只载体。分档只对该配方生效（`isCoopRecipe`），其余 126 个配方的成功率算法零改动。

### 协作结算

- 开炉时快照在场同修（`COOP_RADIUS=6`，上限 4 人，`COOP_BONUS_PER_PARTNER=0.03`），**服务端从 level 读取**，客户端无法提交名单。
- 收丹时二次确认仍在场者才计入：中途离场的不给，没熬过炉时的路人不在快照里也拿不到。
- 快照随批次存 `CoopParticipants` NBT，跨重连/区块卸载存活；结算后立即清空，同一炉次不会重复支付。
- 每位确认同修独立记 `recordAlchemyCompleted`（step 3 为 `SOLO_OR_PARTY`），分成经 `giveOrEnqueue` 走 outbox；**丹本身不按人数倍增**。
- 爆炉与断壳中止也按失败分支结算一次，不因方块销毁而让已投入的同修静默失去所得。

- **step 3 仍只校验 station**，未强制该炉次真的烧了阴芝马载体 —— 在同一座 3 阶丹炉收任意一炉丹同样能过 step 3。要收紧需让 `ALCHEMY_COMPLETED` 支持配方/材料参数（`DetailedQuestProofCatalog` 目前对该类型只允许 `station` 一个参数键），属于路由 schema 变更，未在本批范围内。
- 协作分成暂为灵石碎片/废丹固定一件，未按作者 `peiying_dan_market_low: [80000, 400000]` 的价值区间分档。
- `yy_alchemy_coop` 层作者标注的 `furnace_safety_array`（防爆）陷阱尚无实现，「协作点」目前只是普通丹炉所在地，安全收益未落地。
- 活捕/击杀仍未按 `live_capture_value_low: [20000, 120000]`、`kill_material_value_low: [3000, 15000]` 给价（Y-B 遗留）。
- 协作半径 6 格与 4 人上限、每人 +3% 均为我设定的手感值，作者只给了总成功率区间，实机多人观感待 QA-02 双客户端签字。
