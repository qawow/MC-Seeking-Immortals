# 0.2.153 多方块模型与建造投影

## 变更类别

代码、资源、客户端运行时行为、测试与项目文档更新。继独立的 `0.2.152` 法宝视觉批次后，`mod_version` 从 `0.2.152` 升至 `0.2.153`。

## 完成内容

- 丹炉模板炉颈从 Y=14 延伸到方块边界 Y=16；`AlchemyFurnaceBlock` 的选择/碰撞形状同步为三段联合形状。丹炉盖在上方方块从 Y=0 开始，消除炉体与炉盖之间的世界空间垂直间隙。
- 新增客户端中立的 `MultiblockProjectionCatalog`，以字符串方块 ID 描述 43 个可放置控制器的实体方块、兼容方块和空气孔位，并保存相对层索引。覆盖五阶丹炉、宗门地火室、六档炼器台、制符/傀儡台、灵草圃、巨型聚灵界门、15 个阵心、传送阵、界门和祭坛。
- 新增 `MultiblockProjectionRenderer`：手持控制器显示实时投影；手持结构蓝图台右键受支持控制器锁定/清除投影，并消费该次客户端交互，避免丹炉等控制器同时打开界面或处理手中物品；对空气潜行右键仍走既有启封事务。潜行滚轮切换全部层或单层；缺件、正确方块、错误方块和被占空气孔使用不同颜色提示。客户端事件接入 tick、右键、滚轮、世界渲染及连接生命周期。
- `BaseMaterialItem.useOn` 补齐结构修复台/蓝图台未被投影手势接管时的方块使用服务端路由。
- Fabulous 的 `AFTER_PARTICLES` 阶段使用 Forge 粒子目标透明渲染类型，线框外扩少量 epsilon，降低透明排序和 z-fighting 风险；幽灵方块与线框分批提交，避免复杂结构交错切换渲染目标。

## 验证

定向命令：

```text
./gradlew test --tests com.xunxian.seekingimmortals.structure.StructureToolServiceTest --tests com.xunxian.seekingimmortals.structure.MultiblockProjectionCatalogTest --tests com.xunxian.seekingimmortals.resources.BlockAssetContractTest --no-daemon --max-workers=1
```

结果：三组定向契约与客户端编译通过，耗时 15 秒。随后在当前 `0.2.153` 工作树执行普通 `./gradlew build --no-daemon --max-workers=1`，编译、资源处理、JAR、重映射、生成一致性检查和全量测试均通过，`BUILD SUCCESSFUL in 1m 24s`，`aiPreflight` 正确记录 `mod_version=0.2.153`。此前 75 秒 `runClient` 烟测已完成 Forge 注册、客户端事件订阅和方块/粒子/JEI 图集加载，未出现投影类崩溃；进程按 timeout 终止，仅见环境缺少 flite 与音频设备的既知噪声。
