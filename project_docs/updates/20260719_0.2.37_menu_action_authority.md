# 0.2.37 商店、拍卖与宗门菜单现场权限

## 范围

本批收口 `ShopActionPacket`、`AuctionActionPacket`、`SectActionPacket` 的远程调用和跨菜单重放面，不改商店目录、拍品目录、宗门内容或经济数值。

## 根因

- 三类动作包只携带 action/业务 ID，服务端不要求玩家仍打开对应菜单。
- 三个 hall menu 的 `stillValid` 只检查玩家存活，跨维、离场和来源 NPC 消失后仍有效。
- 市场大厅从任意商人打开后可枚举全部 market shop。
- 宗门动作会再次 `openScreen`，新菜单只绑定玩家当前位置，丢失原执事来源。
- 仅比较 `containerMenu` 仍不能阻止关闭后重新打开同类菜单时重放旧包。

## 实现

- 新增 `MenuAccessContext`：服务端记录打开维度、8 格锚点、可选来源实体 UUID 和非零随机 64 位令牌。
- 显式实体来源为空、死亡或错维时 fail-closed，不再降级为玩家锚点；实体与玩家都必须留在打开时的原始锚点 8 格内。
- Market/Auction/Sect hall 的服务端菜单保存上下文，客户端菜单从 NetworkHooks extra data 接收令牌；`stillValid` 与动作授权复用同一现场判定。
- 三个 C2S 动作包新增 `long accessToken`。处理器先验证当前菜单类型、令牌和现场，再执行同步、购买、竞价、结算、宗门推进或上交。
- Market hall 将 packet shopId 固定到打开时 shopId，客户端只列该店。
- Sect hall 将申请/加入/刷新目标固定到 focus sect；菜单内动作改为数据同步，不创建新菜单。
- Sect hall 的对话、晋升、任务、购买和捐献要求当前宗门等于非空 focus；访问其他宗门执事只提示并拒绝开屏。
- `MarketTraderEntity`、`SectStewardEntity` 直接打开时传入自身；NPC dialogue Session 兼容保存 `SourceEntityId` 与原锚点，延迟 `open_shop` 继承该实体且不能随 NPC 漂移。
- 无实体对话直接记录玩家坐标，不再向实体锚点函数传入空来源；命名宗门对话在展示前复用宗门大厅的他宗成员拒绝门禁。
- 普通命名村民不再按名称进入宗门服务；market/auction/sect 的直接变更命令统一要求 permission 2，只读命令保持开放。
- 31 条 SimpleChannel 消息全部显式限定 `PLAY_TO_SERVER` 或 `PLAY_TO_CLIENT`。

## 兼容性

- `mod_version`: 初始令牌构建到 `0.2.35`，中间权限树构建到 `0.2.36`；提交前锚点 NPE 与命名宗门对话门禁修复触发最终 `0.2.34` -> `0.2.37`。
- `ModNetwork.PROTOCOL_VERSION`: `24` -> `25`。
- 原因：三个已注册 C2S packet 均新增并编码一个 `long` 字段，协议 24 客户端/服务端不能安全混连。
- 显式网络方向进一步收紧不兼容通道行为，本批已因字段变化升至 25，无需重复升版。
- 旧对话 Session 没有 `SourceEntityId` 时按玩家锚点兼容读取，不做数据迁移。
