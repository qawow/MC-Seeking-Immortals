# 0.2.34 秘境奖励与捕捉权限收口

## 目标

- 阻止其他玩家击杀秘境试炼/Boss 后领取奖励、推进任务或解锁他人箱子。
- 阻止试炼/Boss 通过捕捉罐直接 `discard()`，并将捕捉入口收紧为真实生态兽玩法。
- 保持旧 SavedData 可加载，不改变网络包或通道协议。

## 实现

- `SecretRealmProgressSavedData.Session` 增加 UUID `sessionId`；旧存档按 player/realm/enteredAt 生成稳定兼容 ID。
- SavedData 增加 session-scoped encounter claim，当前会话内同一中层、核心或 Boss encounter 只允许成功提交一次，并在会话清理时回收 claim。
- `WorldpackGameplayService` 在成功传送及状态提交后先创建会话，再生成试炼、Boss 和奖励箱。
- 试炼/Boss 实体统一写入 `OwnerUUID`、`SessionId`、`RealmId`、`EncounterId`；非归属玩家及其侍灵不能造成伤害，死亡入口先验证并 claim，随后才执行奖励、图鉴、声望、清关和任务 hook。
- `BeastLootService` 只处理显式 `ecology_beast=true` 的生态死亡，Boss 不再因携带 beast id 旁路领取一套生态掉落。
- 新增 `SecretRealmRewardService`：原版箱子库存保持为空，奖励 ItemStack 序列化到 owner/session 绑定 NBT；授权领取先关闭 claim，再走统一库存余量交付并移除箱子。绑定箱禁止破坏和爆炸，漏斗读取不到奖励。
- 外层、中层、核心和 Boss 缓存均接入托管；附近箱子解锁必须精确匹配 owner/session/realm/encounter。
- 捕捉罐优先选择已削弱的合法候选，只接受显式生态标签、图鉴 `tameable=true`、非真灵、非专属伴生且气血不高于 35% 的目标；Boss、试炼、玩家、NPC、普通怪物和非生态/有主侍灵在写入罐 NBT 或移除实体前拒绝。

## 兼容性

- `mod_version`：`0.2.32` -> `0.2.34`。中间 `0.2.33` 构建后追加残血候选优先修正，preflight 正确要求再次升版。
- `ModNetwork.PROTOCOL_VERSION`：保持 `24`；未修改包字段、顺序、编码、注册或通道行为。
- 旧无 `SessionId` 的 SavedData 可稳定迁移。旧无完整绑定的实体可被清理但不发奖励，避免升级后永久无敌或被旧标签继续领奖。
- 0.2.34 前已放置的普通外层箱/Boss 缓存没有可靠识别标记，无法安全自动迁移，升级存档建议由管理员清理旧秘境壳。

## 剩余风险

- 需要真实多人环境验证两个玩家在同一秘境维度相邻生成时的目标选择、投射物和侍灵归属。
- 需要验证服务端重启、断线重连、双手连续交互、漏斗/活塞/爆炸、满背包掉落和区块卸载。
- NBT 托管领取仍使用现有 at-most-once 交付 helper；进程在关闭 claim 后、世界掉落实体成功前崩溃时仍缺少统一持久 outbox。
- 任务 hook 当前步骤匹配、拍卖/商店事务、远程菜单授权、鉴定消耗和 Curios 飞行资格仍未纳入本批。
