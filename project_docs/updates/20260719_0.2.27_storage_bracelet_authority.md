# 2026-07-19 0.2.27 储物镯实例与嵌套权限

## 范围

修复储物镯菜单的玩家可达 P0：打开副手储物镯 A 后用 `SWAP(40)` 换成 B，关闭菜单会把 A 的独立 handler 快照写入 B，而 A 仍保留原内容；同时关闭储物镯、潜影盒及 capability 容器嵌套入口。

## 实现

- `StorageBraceletMenu` 保存打开时的 `boundBracelet` ItemStack 对象和主手 hotbar 槽，不再在关闭时重新读取当前主手/副手。
- 主手绑定数字键 SWAP 与副手 F-SWAP 在 `clicked` 中早退；原主手槽继续拒绝 pickup，`stillValid` 要求当前手与绑定对象引用相同。
- `removed` 和成功 `quickMoveStack` 仅把 handler 写回 `boundBracelet`，覆盖 Forge Shift-click 部分合并只触发 `setChanged` 的情况。
- `BraceletItemHandler` 在真实内容变化时即时写回绑定对象；初始化加载期间抑制写回，避免按槽加载时覆盖剩余内容。
- handler `isItemValid` 调用 `canStore`。储物法宝、潜影盒、Bundle 以及暴露 `ForgeCapabilities.ITEM_HANDLER` 的物品一律拒绝嵌套；旧嵌套内容仍可取出。
- 储物开屏复用 `ArtifactOwnershipService.canActivate`，并在开屏前拒绝境界不足和完整性为零；旧的取回 helper 使用统一 Forge 余量交付。
