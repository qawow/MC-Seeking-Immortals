# 0.2.263 M-B 本命飞剑实例绑定与迁移

## 更新内容

把本命绑定从「artifact id 关系」改成「**实例**关系」。

### 核心缺陷

本命收益此前全部按同一个模式判定：

```java
if (artifact.id().equals(NatalBindingService.boundId(player))) { ... }
```

这意味着**同 id 的第二件完全继承本命收益** —— 冷却减免、灵力减免、完整度减免、以及成长，一件从未绑定的副本照拿。玩家只要再弄到一把同名飞剑，就凭空多一份本命待遇。

`NatalBindingService` 升到 schema 2：玩家侧根记录 `ArtifactId + InstanceUuid + SchemaVersion + Growth`，目标物品写同一个 `STACK_INSTANCE`。

### 认主不再自动绑定

`ArtifactOwnershipService.claim` 里删掉了 `NatalBindingService.bind` 调用。此前玩家认主的**第一件**法宝就静默成为其唯一本命 —— 与作者「结丹后择一飞剑为本命」的设定直接冲突，玩家甚至不知道自己已经用掉了唯一的本命位。

### 收益点收口（5 处）

- `ArtifactActivationService`：激活成长，以及三个折扣助手 `effectiveIntegrityCost` / `effectiveSpiritualCost` / `effectiveCooldown` 全部新增 `stack` 形参，5 个调用点同步。
- `ArtifactActiveSkillService`：主动技释放成长。
- `ArtifactRefinementService`：祭炼成长。**这处最严重** —— 铸出全新一件就能让背包里的本命成长，现在要求 `holdsBoundInstanceOf` 真的带着那个实例。

### 实例解析 fail-closed

`isBoundInstance` 四重校验：实例 id 非空、两侧相等、artifact id 与 `boundId` 一致、且 `ownerUuid` 必须解析为本人。所以复制 NBT 的载体到他人手里无效。

### 双手绑定仪式

新增 `bindWithEmbryo(player, embryo, target)`：`natal_sword_embryo` + 已认主法宝 + 结丹门槛，潜行右键任一手触发（`ArtifactCatalogItem.use` 在 claim 之前分派，两个方向都识别）。胚只在所有拒绝路径 return 之后才 `shrink(1)`，失败不吞组件；创造模式不消耗。

### 旧档迁移

`isLegacyBinding`（有 id 无实例，或 schema<2）配 `migrateLegacyBinding`：身上**唯一**匹配且已认主的同 id 法宝才收养；多件返回 `AMBIGUOUS`，要求用胚重新择定，不替玩家猜哪把剑。成长值原样保留，不会把长期养成的本命清零。

新增 permission 2 的 `/seeking_immortals artifact natal diagnose`，报告 `法宝 / 实例 / 档案` 三段状态并在可行时迁移。

### tooltip 与激活类型

绑定标记改读 `STACK_INSTANCE`，未绑定的同 id 副本不再显示「本命法宝（已绑定）」。提示改 `bind_hint_embryo` 描述真实的双手仪式，而不是旧的「潜行右键即绑定」。`natal_slot` 保持 deferred 激活类型，并断言 `hasActivation("natal_sword_embryo")` 为 false —— 胚是绑定组件，不是可激活法宝。

## 剩余风险

- **旧档存在过渡态**。`grow` 与命令 `natal grow` 仍只要求 `boundId` 非空，不要求实例；而折扣已要求实例。所以迁移前的旧档会「能成长但不减免」。需要执行一次 `natal diagnose` 才恢复正常。这是我为了不让旧档成长归零而做的取舍，但它确实是一个不自洽的中间状态。
- `AMBIGUOUS` 分支要求玩家再消耗一枚胚。旧档里持有多件同名法宝的玩家等于要付额外成本 —— 相比替他们猜错一把剑，我选了这个，但代价落在玩家身上。
- 实例 UUID 只解决同 id 混淆，**没有解绑路径**。同一实例被交易转手后，物品在他人手里因 `ownerUuid` 不匹配而收益失效，但原主玩家侧的 `boundId`/`InstanceUuid` 记录不会清理，本命位也不会释放。
- `bindWithEmbryo` 未限制 target 必须是 `flying_sword` 类型 —— 任何已认主法宝都能择为本命，与「本命**飞剑**胚」的命名不完全吻合。作者数据里 `natal_sword_embryo` 的 `effect` 是 `bind_flying_sword_natal`，暗示应当限定，但 `natal_artifact_embryo`（本命法宝胚）同时存在，两者的分工作者未写明，故本批未擅自收紧。
