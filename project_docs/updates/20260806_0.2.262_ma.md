# 0.2.262 M-A 维度状态分类

## 更新内容

把维度状态从「`playable` 布尔 + `status` 字符串」换成四个诚实的分类。旧模型把三件互不相干的事混在一起：已实装可进入的世界、按会话实例化的模板、以及只用于分组的逻辑 id。

### 四分类

`DimensionRegistryService.DimensionClass`：

- `PLAYABLE` —— 真实可进入（含 overworld 映射）
- `PREVIEW_LOCKED` —— 只有数据包空壳，实装前关闭入口
- `ABSTRACT_TEMPLATE` —— `dimension_type` 模板，按会话实例化，从不按 id 进入
- `LOGICAL_CLUSTER` —— 分组 id，真实世界是它 `maps_to` 的那些维度

`DimensionDef` 新增该字段并提供两个语义清晰的判定：`enterable()`（普通旅行的唯一权威）与 `pendingImplementation()`（**只有** `PREVIEW_LOCKED` 算待实现）。旧的 `isDeferred()` 整体删除，4 处调用点全部收口。

### 抽象模板与逻辑集群不再算「待实现」

`secret_realm_instance` 是 M09 实例化用的模板，`yin_underworld` 的真实口袋是 `yin_ming_pocket` / `nether_river_pocket` —— 两者都是正确架构，不是待办。现分别归为 `ABSTRACT_TEMPLATE` / `LOGICAL_CLUSTER`，从 `deferredIds()` 移出。

但**入口未放宽**：两者 `enterable()` 仍为 false，普通旅行照样 fail-closed。

### 待实现列表去重

`deferredIds()` 改为按 `pendingImplementation()` 重算并去重。此前 `ingestRegistry` 与 `ingestIndex` 各 `deferred.add` 一次，实测 4 项 / 2 唯一。

### 空壳诚实标注

两个维度此前在撒谎：

- **`immortal_realm`**：作者目录明确标了 `playable: false`、`note: 远期 DLC；当前仅数据占位`，但 `status` 字段为空，于是 `isDeferred()` 返回 false —— 命令显示「可进入」，且 `DimensionTravelService` 只挡 `isDeferred()`，**旅行根本没被拦住**。
- **`asura_realm`**：更乐观。作者目录里的 6 个维度根本不含它，`playable=true` 完全来自 `seedRequired` 的硬种子；数据包 json 只是 `noise` + `nether_wastes` 的空壳。

两者改标 `PREVIEW_LOCKED` 并关闭普通旅行。`inferClass` 让作者写的 `playable: false` 自动落到 `PREVIEW_LOCKED`，不必逐个手工进数据表。

### 数据源收敛

分类由 `catalog/dimensions_reconcile.json` 新增的 `classification` 块单一驱动，`applyClassification` 在所有 ingest 之后应用，所以任何上游索引里的过期 `status` 都无法再决定可进入性。未列出的 id 按自身 status/playable 推断；分类里出现未知 id 记 `warn` 而不是静默丢弃。

这个文件此前**没有任何 Java 读取方** —— 只有测试断言它存在。现在真正接线了。

### 命令展示

`catalogDimensions` / `catalogDimensionGet` 改四类展示，修掉 `def.isDeferred() ? "待实现" : "可进入"` 这个误报源；管理员视图按三个非 playable 类分别列出。

## 剩余风险

- 两个空壳的数据包 json 与飞行规则**故意保留** —— 重分类是状态变更而非删除，已经访问过它们的存档仍能正常加载。但如果玩家当前就站在 `immortal_realm` / `asura_realm` 里，本批既不驱逐也没有加返回路径；他们会被困在原地（可用管理员传送脱出）。
- `spirit_to_immortal`、`immortal_internal` 等作者路线指向仙界，现在会被 `!enterable()` 拒绝。这是预期行为，但作者路线表本身未同步标注「目标未开放」，读数据的人会觉得矛盾。
- `isDirectRouteImplemented` 仍只放行 `mortal_to_tianyuan` 与 `tianyuan_to_fengyuan` 两条，其余 24 条 `access_route` 依旧未实现 —— M-A 未触及这一层，「每个 playable 有可达入口」的断言只验到数据包维度存在，没验到路线真的能走通。
- 分类表目前只有 4 条记录，四分类的实际覆盖面很小；其余 25 个专用秘境维度全部走 `seedRequired` 硬种子的 `playable=true`，未经作者数据确认。
