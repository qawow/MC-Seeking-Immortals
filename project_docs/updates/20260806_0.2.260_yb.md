# 0.2.260 Y-B 阴芝马活捕与运输

## 更新内容

打通「活捕阴芝马」这一步。作者规则：「活的才是丹。死的，只是一堆打折的肉」、「活捕禁制优先；杀光=失败向」、「运出途中死，只剩劣材」。

### 解除三处捕获链阻塞

活捕此前**完全不可达**，三处阻塞叠加：

1. **`capture_only` 未被解析**。`yinyang_yinzhima` 的作者字段是 `tameable: "capture_only"`，而 `isTruthy` 只认 `true/yes/1/capture/tameable`，故 `tameable=false`，`isCapturableTarget` 直接拒绝。
   → `BeastEntry` 新增独立字段 `captureOnly` 与 `capturable()`。**没有**把 `capture_only` 塞进 `tameable`：「可活捕」与「可契约为灵宠」是两种权利，合并会让阴芝马变成宠物，违反作者的 `tame_allowed:false`。
2. **层生成体被当作 trial mob 一律排除**（这是我在 Y-A-2 引入的缺陷）。层名录经 `tagTrial` 绑定归属，而 `isCapturableTarget` 拒绝所有 trial mob，所以我上一批刚让阴芝马能刷出来，同时也让它永远无法被捕。
   → 例外收窄到**仅作者标注 `capture_only`** 的目标；其余 trial shell 与 boss 仍全部排除。
3. **`ecology_beast` 标记为 false**。`TrialCombatShellService` 对专用兽显式 `putBoolean(TAG_ECOLOGY, false)`，而捕获门禁要求该标记。
   → 同样按 `capture_only` 放行，生态刷怪仍是普通捕获池。

### 任务证明 token 对齐

路由 step 2 要求 `entity: yin_zhi_horse`，而层实际生成的是 `yinyang_yinzhima`（Y-A-2 的纠正结果）。`PROOF_ENTITY_MAPPINGS` 新增 `yin_zhi_horse -> yinyang_yinzhima`，沿用既有 mapping+identity 解析器，不放宽校验。

### 活体载体

新增物品 `live_beast_carrier`（活体灵驮笼，`stacksTo(1)`、RARE）与 `LiveCaptureCarrierService`：

- 每次活捕铸新的 `CaptureUuid`，并记 `SourceSession`/`LifeState`/`CapturedAt`/`Tier`，全部存 NBT 以跨重连存活；实例 UUID 使复制的载体无法二次结算同一次捕获。
- 状态机单向 `LIVE → DEGRADED`，**降级而非删除**：超时（`LIVE_TIMEOUT_TICKS=20*60*20`，每 5 秒 tick 检查）与玩家死亡都只把活体转劣材，玩家仍能拿到作者指定的失败分支产出。
- 载体经 `InventoryDeliveryService.giveOrEnqueue` 发放，背包满/掉落/断线走 outbox 恢复，不会因满背包毁掉这次捕获。
- 击杀路径只产劣材（`SPIRIT_BEAST_BONE`），**绝不铸载体、绝不记 `ENTITY_CAPTURED_ALIVE`**，落实「击杀降材料品质」。
