# 2026-07-19 0.2.26 飞升护送与库存事务

## 范围

延续全仓库 max 子代理审计，修复三个玩家可达的 P0：飞升传送被取消后仍提交成功并清空行囊、护送完成递归及 inactive 代理完成、奖励或退款部分入包后再次掉落完整副本。

## 实现

- 飞升删除 worldpack 失败后的第二次传送路径，只执行一次天渊直传；传送后验证实际 `ServerLevel` 与目标距离，验收失败按原槽恢复备份。
- `FLAG_LOADOUT_CONFIRMED`、pending 清理、worldpack 区域/返程/秘境状态、飞升与阶段标记、起步礼均位于成功验收之后；目标平台也只在验收后铺设，回滚快照在飞行刷新和起步礼前清除。
- 护送调用方向收为 `ModEvents -> SectMissionGenerator -> EscortMissionService`。服务不再回调生成器，而是校验活动状态、实体 UUID、escort 标签、owner、存活与距离后返回 boolean。
- 执事交互传入实际 `SectStewardEntity`；只有当前 generated mission 类型为 escort，且护送实体同时在玩家和本次执事 5 格内才写完成标记。丢失、无 UUID、错误 owner 和 inactive 均拒绝。
- `addFreshEntity` 失败时不持久化 generated mission，并显示双语失败消息；创造模式上交同样清理残留护送实体。
- 新增 `InventoryDeliveryService`，按物品最大堆叠拆分后调用 Forge `ItemHandlerHelper.giveItemToPlayer`；其内部写主背包并直接生成真实 remainder 实体，不经过可取消的玩家丢弃事件。
- 将 17 个危险点迁移到统一交付：拍卖 3、Boss 掉落 2、Boss 遭遇 1、秘境试炼 3、文本任务 3、妖兽掉落 3、制符 1、剧情唯一奖励 1。
- 飞升起步礼也迁入统一交付，部分背包容量不会再吞掉未插入的碎片。
