# 2026-07-19 0.2.31 炼器配方权限收口

## 范围

移除法宝从 vanilla 工作台直接产出的旁路，确保境界、炼器炉阶、成功率、失败损耗、认主与初始祭炼层只由权威炼器服务处理。

## 实现

- 审计 68 个 `refine_*.json`：24 个为 `minecraft:crafting_shaped`，44 个为 `seeking_immortals:refinement`。
- 删除全部 24 个工作台近似配方；其中 13 个已有同名自定义 serializer，另外 11 个新增显式 serializer，不移除法宝本身或目录配方。
- 7 个旧 serializer 的材料数量/种类对齐 catalog，删除不同命名的重复定神珠 serializer；现有 55 个 custom serializer 均唯一映射 catalog。
- 保留三阶炼器炉结构门禁。权威路径继续负责境界/炉阶校验、材料扣除、成功率、失败残骸、owner 与 refinement layer；G4-G6 数据不会在当前 G1-G3 炉越级执行。
- 从 `ResourceJsonParseTest` 移除 23 个锁定旧工作台近似配方的正向测试，保留全资源 JSON 与 Patchouli 布局校验。
- 新增并强化 `ArtifactRefinementRecipeAuthorityResourceTest`：扫描全部 artifact/refinement catalog 输出和整个 recipes 目录，禁止任何 `minecraft:crafting_*` 产出法宝；要求所有 `refine_*.json` 使用自定义 serializer；对全部 custom serializer 检查唯一 catalog 映射、id-map 冲突、材料多重集、产物、境界、炉阶和基础成功率。

## 遗留

真实客户端、专服和多人环境仍需烟测 G1/G2/G3 结构、JEI/配方书刷新、材料匹配和失败残骸。G4-G6 只有 catalog/serializer 数据，尚无对应权威炉方块与结构，不能通过低阶炉执行。下一高风险批次转向死亡 Clone 永久账本与极端走火保留物迁移。
