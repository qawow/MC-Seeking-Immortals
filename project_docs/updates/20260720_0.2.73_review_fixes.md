# 0.2.73 代码审查修复批次

## 审查方式
按用户指令，多子代理并行审查 0.2.65–0.2.72 批次与核心权威路径（多方块运行态、交付 outbox、消耗品/成功率缩放），逐条验证后修复确认缺陷。

## 已确认并修复的缺陷

1. **见闻事件大小写失配（高）**：`FactionQuestCatalogService.load` 保留原大小写键，而全部查询按小写归一 → `A4_/M1_/E_` 等 35+ 条见闻事件运行时不可达（残图/探报/舆图/见闻命令全部失效）。载入时统一小写键，Entry 保留原 id 供 UI。
2. **地渊通行令走错权威（高）**：`diyuan` 是秘境而非区域卡，`travel()` 必然失败。改走 `enterSecretRealm`。
3. **G2 炼器台无结构目录条目（高）**：结构目录只有 g1/g3，0.2.71 的 ensureCommissioned 与效率查询在 G2 台永远拿 0 效率（成功率地板 0.03）。补 `refinement_forge_g2` pattern 条目 + 专用 validator 分发 + 效率查询与 G2 方块门禁修正。
4. **repair 绕过建站（中）**：DISABLED（未启封）工站可用碎片 repair 逐步拉回运行态，绕过 form 的结构材料成本。repair 现对 DISABLED fail-closed 并提示先 form/overhaul。
5. **outbox 满额静默丢弃最旧奖励（中）**：64 条上限时 `entries.remove(0)` 永久丢失未领取物。上限提至 256，满额时优先向最新同类条目合并，不再静默丢弃。
6. **discoverLore 失败仍吞物品（中）**：chronicle 查询失败时仍返回成功 → 残图被消耗且双重消息。改 fail-closed。
7. **refund 标志过早置位（低）**：`InventoryReservation.refund` 循环前置 `refunded=true`，中途异常丢尾部退款。改为循环完成后置位。
8. **拍卖请柬按次消耗（低）**：作为凭证改为耐久（不随使用消耗），与宗门令牌一致。
