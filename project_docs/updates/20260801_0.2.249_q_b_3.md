# 0.2.249 Q-B-3 物品获取、制作、炼丹与交付事件的结构化任务证明

## 范围

本批实现后续实施计划 Q-B-3：为物品获取（ITEM_ACQUIRED）、制作（CRAFT_COMPLETED）、炼丹（ALCHEMY_COMPLETED）和交付（ITEM_DELIVERED）事件补齐结构化任务证明生产与校验，并注册 6 个此前缺失的故事载体物品。不含网络包字段、顺序、类型、注册或频道行为变化，`ModNetwork.PROTOCOL_VERSION=31` 保持不变。

## 完成内容

### 新注册载体（6 个 bulk 物品）

`tai_yang_jing_huo`（太阳精火）、`five_cold_flames`（五寒焰）、`silver_tadpole_script`（银蝌文残页）、`dragon_scale_fruit`（龙鳞果）、`blank_letter`（无字信）、`gray_realm_clue`（灰界线索）——加入 `catalog_bulk_items.json`（1195 条），补齐中英双语名称/说明、生成物品模型与确定性纹理，随 bulk 管线注册并进入创造栏。这些是 deity_huoyu_path / reincarnation_intro / court_hunt_gray 等步骤此前缺失的真实载体。

### 可靠物品令牌映射（纯函数）

`DetailedQuestProofService.itemsProvingToken(routeToken)`：路由令牌 → 可证明它的真实规范物品集合；别名令牌经 `ItemCatalogService.resolveId` 折叠（jiao_pearl→water_pearl、lingzhu_fruit→fire_spirit_fruit）；概念令牌显式映射真实物品（spirit_herb→blood_forbidden_herb/spirit_herb_bundle、xutian_map_fragment→void_palace_map_fragment、survival_preparation→五件生存套装、fire_resist_ready→yang_flame_talisman、fire_toad_resistance→阳焰符+祛毒丹、realm_gate_token→灵界通行符/券）。身份规则仅对真实载体（bulk meta 或专用注册白名单）生效，概念令牌自身不视为物品，失败关闭。

### 校验

- ITEM_ACQUIRED / CRAFT_COMPLETED / ITEM_DELIVERED：自然事件要求玩家当前真实持有可证明路由令牌的物品（服务端背包扫描）；历史回放只使用服务端记录过的事实。
- ALCHEMY_COMPLETED：事件站台与路由站台按别名规范折叠等价（alchemy_furnace_g3 → alchemy_furnace）。
- 路由匹配允许事件物品 ∈ 令牌证明集（`routeItemMatches`），客户端字符串永不作为可信输入。

### 生产点接线

- `QuestHookRuntime.onItemPickup` → `recordItemAcquired`（取代旧 `recordAndAdvance(player, itemId)` 字符串路径）。
- `QuestHookRuntime.onItemCrafted` → `recordItemCrafted`。
- `AlchemyFurnaceBlockEntity.giveOutput` → `recordAlchemyCompleted(player, "alchemy_furnace_g"+tier)`（领取完成批次即完成炼丹，站台来自服务端炉级）。
- `QuestHookRuntime` turnin_quests → `recordItemDelivered(player, npcId)`：仅当玩家真实持有可证明物品且交付 NPC 匹配链 giver 或当前步骤 place。

### 账本顺序修复

`record()` 的账本去重检查移到 `handledChains` 一步/链槽位之前：同一链内多个路由匹配同一事件（如 court_hunt_gray 第 2/4 步均为 ITEM_DELIVERED gray_realm_clue）时，已记账路由不再吞掉后续路由的推进机会，交付两次可正常完成两步。

### 历史与回放

HISTORY_TAG 物品记录携带 `Item`/`Station` 字段；`eventFromHistory` 可按物品/站台重建事件；物品事实只回放服务端记录过的历史。
