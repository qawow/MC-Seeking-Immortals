# 0.2.162 全域作者视觉生命周期收口

## 变更类别

代码、资源、构建校验、测试与项目文档更新。工作树前序视觉子步骤已推进至 `0.2.161`，本轮按规则将 `mod_version` 升至 `0.2.162`。追加客户端生命周期包改变频道消息表，因此同步升级网络协议。

## 统一作者目录

- `generate_authored_visual_catalog.py` 将 29 份运行时目录与 v118-v122 作者视觉资料确定性编译为 schema 3 资源：17 个 domain、3,779 个 profile、18,395 个 timeline event 和 80 个域内 alias。
- 每条 profile 保存真实运行时 id、family、motif、particle、trail、palette/ARGB、半径、强度、state、timeline、来源与 fallback 状态；Java 加载器校验真实 `TechniqueVfxPalette.Family`、`TechniqueVfxPacket.Motif`、粒子/拖尾白名单和数值边界。
- Realm v118 基础卡与 v120 光雾卡按显式 crosswalk 合并；22 个状态对齐 v119 的 12 张真实 `fx_*` 样式卡。没有运行时 realm id 的 `light_spirit_border` 留在 `unmapped_visuals`，不虚构映射。
- 三个确定性校验任务已接入 Gradle `check`：统一目录、视觉粒子/拖尾/beam、状态图标。

## 资源与客户端渲染

- 新增 12 种模组命名空间 Lodestone 粒子及 provider；生成 12 张 16x16 粒子、8 张 64x8 拖尾、1 张 64x16 beam 和 22 张 18x18 状态图标。
- `LodestoneTechniqueVfx` 与 `LodestoneWorldGeometry` 使用作者 profile 的精确 ARGB、粒子、拖尾和世界几何；投射物实体同步 profile/family/trail，旧存档按名称/序号安全回退。
- 状态栏替换为最多 6 个可读作者图标并显示有界溢出数量；原版/第三方效果仍按其注册命名空间读取图标。

## 生命周期与时间轴

- 新增仅 `PLAY_TO_CLIENT` 的 `VisualEventPacket`，字段有长度、坐标、实体 id、时长、年龄、缩放、强度和优先级上限；支持 WORLD/ENTITY/BLOCK 锚点与 START/UPDATE/STOP/SNAPSHOT/EVENT，包只携带视觉意图，不改变服务端玩法权威。
- `ClientVisualEngine` 统一跟踪实例、解析锚点、执行租约和共享预算：最多 256 个活动实例、96 个可见实例；ALL/DECREASED/MINIMAL 分别限制 192/112/48 粒子与 48/24/10 世界几何，每帧最多 4 个后效。
- `VisualTimelinePlan` 先匹配 packet state，再匹配 typed trigger，按作者 start/duration 重基准；持续实例循环并在续租/状态变化时清理发射记录，一次性 EVENT 也拥有受实例上限保护的有限 timeline。
- timeline action 映射到现有受预算 renderer kind，并覆盖作者 particle、trail、radius 与 intensity。Boss P1/P2/P3、阵法 ACTIVE/PULSE、状态 APPLY/TICK/EXPIRE、渡劫 WAVE/SUCCESS/FAILURE 及术法 storyboard 不再退化为统一固定心跳。

## 生产接线与加固

- 术法、法宝、丹药/消耗品、状态、阵法、多方块、火球/飞剑、Boss、灵兽、NPC、载具、秘境/区域、世界危害和渡劫成功路径接入统一 dispatcher；失败的玩法事务不会因视觉层而变成成功。
- 客户端切换 `ClientLevel` 会清理旧实例；ENTITY 一次性/STOP 在实体未同步或已移除时回退包内坐标；UPDATE 年龄回退会重置 timeline/心跳节流。
- Boss 状态可交替进入 ATTACK；死亡先停止持续实例再发 DEATH，后续离场不会重复 STOP；死亡实体不再继续 tick 刷新。
- 方块视觉只在作者 profile 存在时发送，并限制每维每 tick 32 包。物品视觉读取使用 `getTag()`，不会为纯显示创建空 NBT。
- 世界危害使用 80 tick 租约、40 tick 刷新；缓解状态变化先停止旧 profile，危害实例键与普通 status 隔离。灵舟实体每 40 tick 发送载具 UPDATE。
- `TRUE_IMMORTAL` 明确映射 `final_ascension`；CORE_FORMATION 至 TRUE_IMMORTAL 八个渡劫目标均解析有效 profile，成功/失败显式 STOP 持续实例。

## 剩余风险

- 自动测试不能替代真实客户端视觉验收；多人密集粒子、最低粒子档、透明排序、Fabulous/Fast 差异、跨维度切换、长时间状态续租和真实 Boss/阵法/渡劫阶段仍需人工检查。
- `SCREEN_OVERLAY` 与 `MODEL_ANIMATION` 当前分别投影为受预算的 SCAN/STATUS 表现；本批没有引入任意实体模型动画或通用全屏后处理解释器。
- `WorldHazardVfxService.clear()` 在换维后可能在新维度发送一次无匹配旧实例的 STOP 消散；客户端切维会先清空实例，因此只剩短暂纯视觉风险。
- 异常/旧 NBT 使用默认 `spirit_boat` id 时没有专用 vehicle profile；正常载具生成路径写入真实目录 id，不受影响。
